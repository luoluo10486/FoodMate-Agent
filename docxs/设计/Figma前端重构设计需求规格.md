# FoodMate 前端重构 Figma 设计需求规格

版本：v0.2（范围确定稿）  
日期：2026-07-30  
用途：作为 Figma AI 生成 FoodMate 用户端与管理端高保真设计稿的主输入；设计确认后，再通过 Figma MCP 落地为前端代码。  
适用端：响应式 Web（桌面端优先，同时完整覆盖平板与移动端）。  

> 本文是设计需求，不代表所有功能已经由后端实现。页面和功能按“当前可接入”“已有前端占位”“目标态待建设”明确标注，禁止在设计评审时把目标态误报为已完成。

---

## 1. 设计任务

为 FoodMate 设计一套完整、长期稳定、可开发落地的产品界面。FoodMate 是面向饮食记录、营养分析、备餐规划和知识问答的任务型 Agent 工作台，不是普通聊天机器人，也不是营销网站。

本轮 Figma 必须同时覆盖：

1. 用户认证与账号恢复。
2. 用户端 Agent 工作台、会话、个人饮食记录、分析、规划、知识库和个人中心。
3. 用户可控记忆、登录设备、数据导出和账号注销。
4. 管理端概览、用户、Agent 运行、工具、模型用量、知识库、删除资源和操作审计。
5. 加载、空、错误、无权限、离线、执行中、等待确认等关键状态。
6. 桌面、平板、移动端的主要页面与导航行为。

设计产物必须是可开发的产品界面，不制作首页宣传站、插画型落地页或只有理想状态的静态效果图。

## 2. 产品定位与边界

### 2.1 产品目标

FoodMate 帮助用户通过自然语言或结构化入口完成以下任务：

- 计算：热量、营养、份量和单位换算。
- 记录：创建和修正饮食记录，查询历史饮食。
- 分析：查看热量、蛋白质、碳水、脂肪和目标达成趋势。
- 规划：生成多日餐单、备餐步骤、预算估算和购物清单。
- 问答：查询食材保存、烹饪和营养知识，并展示来源。
- 记忆：在用户确认后保存忌口、过敏原、目标和常用偏好。

### 2.2 安全边界

- 不提供医疗诊断、治疗、处方或紧急健康决策。
- 涉及疾病、高风险症状、孕期、严重过敏等内容时，界面必须显示安全降级提示和专业咨询建议。
- 数值结果应显示口径、数据来源或“估算”标识，不能把估算包装为精确医疗结论。
- 写入饮食日志、保存计划、保存长期记忆、追加运行预算等有副作用操作，需要清晰预览和确认。
- 不向用户展示内部 Prompt、隐式推理过程、密钥、原始异常堆栈或不必要的基础设施细节。

### 2.3 目标角色

| 角色 | 主要目标 | 权限原则 |
|---|---|---|
| 未登录访客 | 登录、注册、找回密码 | 不访问个人数据和工作台 |
| 普通用户 | 记录、分析、规划、问答、管理个人数据 | 只能访问自己的数据；首个正式版本仅支持个人使用 |
| operator | 查看运行、工具、用量、知识库等治理信息 | 默认只读，不执行高风险写操作 |
| admin | 管理用户、工具、知识、软删除资源和系统治理 | 写操作二次确认并写入审计 |

## 3. 实现事实与设计范围

### 3.1 当前已有真实接口，可优先落地

- 注册、登录、退出、找回密码、重置密码。
- 当前用户资料读取与更新、修改密码、头像上传与删除。
- 登录设备/认证会话查看、单个下线、全部下线。
- 个人数据导出任务、一次性下载、账号注销申请。
- 会话列表、搜索、创建、改名、归档、取消归档、软删除、恢复。
- 会话消息读取、发送、修改和删除。
- AgentRun 创建、状态查询、SSE 事件、取消、预算追加。
- 用户记忆列表、编辑、删除和确认。
- 管理端概览数据、用户列表、用户状态修改、强制下线。
- 管理端知识文档上传/状态修改、工具状态修改、软删除资源恢复。

### 3.2 当前前端已有，但主要为 mock 或占位

- 摄入分析页。
- 餐食规划与购物清单页。
- 用户知识检索页。
- 管理端部分运行、工具、模型用量、知识和审计表格。
- Tool Trace、引用、追问、写入确认、结果卡等 Agent 组件。

### 3.3 首版确定纳入、后端仍需补齐

- 独立饮食记录台账及其筛选、编辑和记录管理。该页面已确定纳入首个开发版本，Agent 负责自然语言录入，记录页负责结构化查看和维护。

### 3.4 后续目标态必须先设计，后端仍需补齐

- 分析页真实业务数据、图表对比和导出。
- 计划版本、保存、复制、调整、购物清单状态同步和导出。
- 用户知识检索真实接口和完整文档详情。
- 管理端运行详情、事件时间线、DLQ/恢复、预算治理等完整操作接口。
- 通知中心与异步任务统一收件箱。

设计时必须覆盖这些目标态，但应使用真实可解释的数据结构；不能为不存在的社交、支付、商城或插件市场擅自增加页面。

## 4. 全局信息架构

### 4.1 用户端主导航

桌面端采用固定左侧工作区导航，建议宽度 248px，可折叠为 72px 图标栏：

1. FoodMate 品牌标识。
2. 主操作“新建任务”。
3. 一级导航：
   - 工作台
   - 饮食记录
   - 摄入分析
   - 餐食规划
   - 知识库
4. 会话区域：搜索、最近会话、已归档入口、回收站入口。
5. 底部：Tools 状态、Agent 状态、帮助/反馈入口、用户菜单。

用户菜单包含：

- 个人中心
- 记忆与偏好
- 登录设备
- 管理后台（仅 admin/operator 可见）
- 退出登录

### 4.2 用户端建议路由

| 路由 | 页面 | 说明 |

| `/login` | 登录/注册/找回密码 | 访客入口 |

| `/` | 工作台首页 | 新任务与近期概览 |
| `/chat/:sessionId?` | Agent 会话 | 核心任务执行页 |
| `/records` | 饮食记录 | 目标态新增 |

| `/knowledge` | 用户知识库 | 检索与引用 |
| `/profile` | 个人中心 | 资料总入口 |
| `/profile/memories` | 记忆与偏好 | 长期记忆管理 |
| `/profile/security` | 安全与设备 | 密码和认证会话 |
| `/profile/data` | 数据与隐私 | 导出和注销 |

### 4.3 管理端主导航

- 概览
- 用户管理
- Agent 运行
- 工具调用与 SQL 审计
- 模型用量
- 知识库
- 工具注册表
- 删除资源
- 操作审计

首版主导航不包含“运行治理”。准入队列、预算追加记录、恢复任务、DLQ 和 Proposal Inbox 仅保留为后续设计附录，待管理接口、权限和幂等安全契约成熟后再启用。

管理端导航底部始终显示当前权限：`admin 可操作` 或 `operator 只读`，并提供“返回 Agent 工作台”。

## 5. 全局页面框架

### 5.1 用户端框架

- 左侧：主导航和会话列表。
- 顶部：当前模块标题、页面级筛选/状态、用户头像。
- 中部：当前页面主工作区。
- 会话页右侧：可折叠的工具、引用和运行轨迹面板。
- 会话页底部：固定输入器，主内容区独立滚动。

### 5.2 管理端框架

- 左侧：管理导航与权限说明。
- 顶部：页面标题、环境标识、数据更新时间、刷新、当前管理员。
- 中部：紧凑的数据表、筛选条、详情抽屉和操作弹窗。
- 管理端应是高信息密度、安静、易扫描的操作界面，不采用大量装饰性卡片。

### 5.3 全局顶层状态

每个受保护页面必须设计：

- 初次加载骨架屏。
- 内容为空且有下一步动作。
- 局部请求失败与重试。
- 整页不可用。
- 登录过期，提示重新登录且尽量保留未提交内容。
- 无权限 403。
- 网络离线/重连。
- 操作成功的轻量反馈。
- 高风险操作的二次确认和失败原因。

## 6. 用户端页面详细规格

## 6.1 登录、注册与密码恢复

### A. 登录视图

字段：

- 用户名或邮箱。
- 密码，带显示/隐藏图标。
- 可选“保持登录”复选框；若后端不支持，不在首版实现中启用。

按钮与链接：

- `登录`：主按钮；提交中显示加载并防止重复提交。
- `注册账号`：切换至注册视图。
- `忘记密码`：切换至找回密码视图。

状态：字段校验、凭证错误、账号锁定、账号禁用、服务不可用、登录成功跳转。

### B. 注册视图

字段：用户名、邮箱、密码、确认密码。显示密码规则和逐项满足状态。

按钮：

- `注册`。
- `返回登录`。

### C. 找回与重置密码

- 找回页：邮箱、`发送重置邮件`、`返回登录`。
- 提交成功后使用中性提示，避免泄露邮箱是否注册。
- 重置页：新密码、确认密码、`确认重置`、`返回登录`。
- 必须设计 Token 无效、过期、已使用三种状态及“重新发送”动作。

## 6.2 工作台首页

目标：让用户在首屏内立即开始任务，同时看见必要的近期信息；不是产品宣传页。

### 页面区域

1. 紧凑欢迎区：品牌名、问候语、当前日期，不使用超大 Hero。
2. 主输入器：支持多行自然语言输入。
3. 高频任务入口：
   - 记录一餐
   - 分析最近摄入
   - 制定餐食计划
   - 查询食材知识
   - 快速营养计算
4. 今日摘要：已记录餐次、热量/蛋白质相对目标、待确认记录。
5. 最近任务：最近 3 至 5 个会话或计划，可继续。
6. 待处理事项：等待用户确认的写入、预算追加、记忆确认或失败任务。

### 按钮与交互

- `新建任务`：创建空会话并聚焦输入框。
- 发送图标：有内容时可用；空内容禁用。
- 附件图标：预留食物照片/文件入口，首版未接入时不要做可点击假按钮。
- 高频任务按钮：把对应模板带入输入器，允许用户修改后再发送。
- `继续任务`：进入对应会话。
- `查看全部`：进入对应模块。
- Tools/Agents 状态按钮：展开能力与运行状态面板。

### 状态

- 新用户：没有假数据，显示四个可执行起始任务。
- 有数据用户：显示今日摘要和最近任务。
- 数据加载失败：摘要区域局部重试，不能阻塞新任务输入。

## 6.3 Agent 会话页

这是产品核心页面，必须完整设计全部运行状态。

### A. 左侧会话区

顶部按钮：

- `新建任务`。
- 搜索图标/搜索框。
- 筛选菜单：全部、进行中、已完成、已归档。

每条会话显示：标题、最后一条摘要、更新时间、状态点。悬停或聚焦后显示更多菜单：

- 重命名
- 归档 / 取消归档
- 删除到回收站

附加入口：

- `已归档会话`
- `会话回收站`

回收站内操作：`恢复`。永久删除当前没有真实接口，不设计为可执行主操作。

### B. 会话顶部栏

- 可编辑会话标题。
- 当前运行状态。
- 更多菜单：重命名、归档、删除。
- 移动端显示打开会话列表的菜单按钮。

### C. 消息流

消息类型必须视觉可辨：

- 用户消息。
- Agent 普通回答。
- 运行状态条。
- 澄清卡。
- 写入确认卡。
- 预算追加确认卡。
- 结构化结果卡。
- 引用块。
- 工具错误/安全降级提示。

用户消息操作：复制；对允许修改/删除的历史消息显示更多菜单，但必须提示修改历史消息不会自动改写已完成的旧回答，重新执行应生成新 Run。

Agent 回答操作：

- 复制
- 查看引用
- 查看运行详情
- 基于结果继续提问
- 重试（仅失败或明确允许重跑时）

不设计点赞、分享至社交平台等未定义功能。

### D. Agent 状态条

覆盖状态：

- queued / routing：正在接收与识别任务
- planning：正在拆解任务
- retrieving：正在检索资料
- executing_tools：正在执行工具
- validating：正在校验结果
- composing：正在生成回答
- waiting_user：等待补充或确认
- completed：已完成
- failed：失败
- cancelled：用户已停止
- superseded：已由新的接续运行替代

状态条展示当前阶段、已经耗时、可理解的下一步；不要展示模型隐藏思维过程。

### E. 澄清卡

- 只展示 1 至 3 个当前必要问题。
- 选项问题使用单选、复选或快捷选项，不用自由文本模拟选择器。
- 数量、预算、日期等使用对应输入控件。
- 按钮：`提交并继续`、`取消任务`。
- 用户回答后保留只读摘要，避免上下文消失。

### F. 写入确认卡

用于饮食记录、计划保存、记忆保存等副作用操作。

内容：目标对象、结构化数据预览、来源/假设、可能影响。

按钮：

- `确认保存`：主按钮。
- `修改内容`：返回编辑态。
- `取消`。

### G. 预算追加确认卡

显示：达到预算上限原因、已消耗 Token/成本、建议追加额度、继续后的影响。

按钮：

- `继续并追加预算`
- `调整额度`
- `结束任务`

禁止固定写死一个额度而不给用户查看；设计需预留 Token 和金额输入及服务端限制提示。

### H. 右侧轨迹面板

采用 Tab：`运行`、`工具`、`引用`。

运行 Tab：Run ID（可复制）、状态、开始/结束时间、耗时、预算、重试/接续关系、错误码。  
工具 Tab：工具名、状态、耗时、重试次数、输入/输出摘要、是否需确认、错误原因。  
引用 Tab：来源标题、片段、相关度/元数据、打开详情。

工具失败必须可见，但用户端只显示可理解的错误摘要；原始参数和敏感数据默认折叠或脱敏。

### I. 底部输入器

控件：

- 多行输入框。
- 附件入口（未接入时隐藏）。
- 发送图标按钮。
- 运行时替换为停止图标按钮。
- Tools 与 Agents 状态入口。

行为：Enter 发送、Shift+Enter 换行；中文输入法组合输入期间不得误发送。发送失败保留文本。流式输出时输入器高度稳定。

### J. 会话页必做状态画板

1. 空会话。
2. 正在 planning。
3. 工具执行中。
4. 等待澄清。
5. 等待写入确认。
6. 达到预算上限。
7. 正常完成并带引用。
8. 工具失败且可重试。
9. 安全降级结果。
10. 用户取消。
11. SSE 连接中断并自动重连。

## 6.4 饮食记录页（首版正式范围）

目标：结构化管理饮食记录，同时保留“用自然语言记录”的低门槛入口。

### 页面区域

- 日期切换：上一天、日期选择、下一天、回到今天。
- 日汇总：热量、蛋白质、碳水、脂肪、餐次完整度。
- 餐次分组：早餐、午餐、晚餐、加餐；每组显示时间和小计。
- 记录项：食物名、份量、单位、营养估算、来源、确认状态。
- 周期视图切换：日 / 周。

### 按钮

- `记录一餐`：打开自然语言快速记录抽屉。
- 加号图标：在对应餐次新增食物。
- 编辑图标：编辑记录。
- 删除图标：二次确认后软删除。
- 复制图标：复制到今天或指定日期/餐次。
- `待确认`：进入确认卡。
- `分析这一天`：跳转分析页并带日期范围。

### 新增/编辑抽屉

字段：日期、餐次、时间、食物名称、份量、单位、备注、营养数据来源。允许一个餐次添加多项食物。

操作：`保存记录`、`保存并继续添加`、`取消`。

状态：无记录、部分缺失营养、估算值、待确认、保存失败、已软删除。

## 6.5 摄入分析页

目标：让用户看懂统计口径、趋势、目标差距和可执行建议，而不是只展示图表。

### 顶部筛选

- 时间范围：7 天、30 天、90 天、自定义。
- 对比：上一周期 / 不对比。
- 数据范围：全部餐次或指定餐次。
- `导出报告`（目标态）。

### 核心内容

1. 指标条：平均热量、蛋白质、碳水、脂肪、记录天数、目标达成率。
2. 趋势主图：可切换热量、蛋白质、碳水、脂肪。
3. 目标区间：用背景带显示目标范围，图例明确。
4. 营养结构：宏量营养素占比，不使用难以比较的纯装饰图。
5. 数据完整性：缺失天数、估算记录占比、统计口径。
6. 洞察列表：事实、风险、建议分开表达。
7. 关联记录：点击异常点可打开当天记录抽屉。

### 按钮

- 指标分段控件。
- `查看当天记录`。
- `让 Agent 解读`：带当前范围进入会话。
- `基于分析制定计划`：带目标差距进入规划。
- `导出报告`：异步任务时显示进度和完成通知。

### 状态

- 无数据：引导“记录第一餐”。
- 数据不足：显示已有事实，不强行生成趋势结论。
- 部分数据缺失：图表断点和缺失提示。
- 加载/失败：图表尺寸稳定，局部重试。

## 6.6 餐食规划页

目标：创建、校验、保存和执行多日餐食计划及购物清单。

### A. 计划列表/入口

- 当前计划、草稿、已归档。
- `新建计划`。
- 每个计划显示日期范围、人数、目标、预算、状态、最近更新时间。
- 更多菜单：重命名、复制、归档、删除。

### B. 新建计划向导

步骤建议：

1. 基本范围：开始日期、天数、餐次；首版固定为当前用户本人，不显示人数或家庭成员控件。
2. 目标与限制：营养目标、预算、忌口、过敏原、饮食模式。
3. 执行条件：设备、备餐时长、食材复用、已有食材。
4. 确认并生成：约束摘要和冲突提示。

按钮：`下一步`、`上一步`、`保存草稿`、`生成计划`、`取消`。

### C. 计划详情

- 顶部：计划名称、日期、状态、预算、`编辑约束`、`重新生成`、`保存计划`。
- 多日菜单表：日期为列或分组，餐次为行；移动端改为按天折叠列表。
- 每餐显示菜品、份量、营养摘要、预计成本、备餐时间。
- 单餐菜单：替换菜品、调整份量、复制、删除。
- 校验面板：营养、预算、过敏原、食材复用和时间约束。
- 备餐步骤：按批次和先后顺序排列，可勾选完成。

### D. 购物清单

- 按蔬菜、肉蛋奶、主食、调味品等分类。
- 每项显示数量、单位、对应餐次、估算价格、已有/待买/已买状态。
- 支持勾选、分类全选、添加自定义项、编辑数量、删除。
- `仅看待买`、`按购买地点分组`（目标态）。
- `导出/打印`、`复制清单`。

### E. 冲突与失败

- 约束冲突时明确指出哪几项无法同时满足，提供可选择的放宽建议。
- 生成失败保留全部约束，提供 `重试` 和 `修改约束`。
- 重新生成必须提示会影响哪些未锁定餐次；允许锁定满意的餐次。

## 6.7 用户知识库页

目标：搜索可信的食材、烹饪和营养资料，并可以把结果带入 Agent 会话。

首版内容边界：普通用户只能检索由管理员维护并已上线的知识库内容，不提供私人文档上传、个人文档列表、存储配额、可见性设置或个人索引管理。

### 页面区域

- 大搜索框：支持关键词和自然语言问题。
- 筛选：主题、来源类型、更新时间；若没有真实字段则隐藏对应筛选。
- 结果列表：标题、摘要、来源、更新时间、可见性、匹配片段。
- 右侧或抽屉详情：完整引用元数据、相关片段、原文入口（若允许）。

### 按钮

- 搜索图标按钮。
- `查看引用`。
- `用此资料提问`：带引用上下文创建会话。
- `清除筛选`。

用户端不显示上传、编辑、删除、上线、下线或重新索引按钮；这些能力只属于管理端知识库。

状态：初始推荐主题、无结果、检索失败、来源不可访问。不要显示“3 个 mock 文档”等开发文案。

## 6.8 个人中心

个人中心采用二级导航或 Tabs：`基本资料`、`记忆与偏好`、`安全与设备`、`数据与隐私`。

### A. 基本资料

区域：

- 头像：预览、选择/替换、删除；展示格式、大小限制和上传进度。
- 账号只读信息：用户名、邮箱、角色、账号状态、创建时间、最近登录。
- 饮食画像：展示名、性别（可选）、身高、体重、活动水平、饮食目标、热量目标、蛋白质目标、过敏原、忌口、常用单位。

按钮：`保存资料`、`放弃更改`、`选择图片`、`删除头像`。

交互：离开有未保存内容的页面时提示；角色和账号状态不可编辑。

### B. 记忆与偏好

顶部说明：FoodMate 只在用户确认后将候选内容保存为长期记忆，用户可随时修改或删除。

筛选：全部、待确认、已确认；类别包含偏好、忌口、过敏原、目标、单位、常用餐型。

每条记忆显示：内容、类别、状态、来源会话、创建/更新时间、最近使用时间（若有）。

按钮：

- `确认`（待确认项）。
- 编辑图标。
- 删除图标，需确认。
- `查看来源会话`。

空态：说明没有已保存记忆，并提供“去会话中告诉 FoodMate”动作。

### C. 安全与设备

- 修改密码：当前密码、新密码、确认密码、密码规则；按钮 `更新密码`。
- 当前设备高亮。
- 设备列表：设备/浏览器、IP、创建时间、最近活动、过期时间、状态。
- 单项按钮：`退出此设备`。
- 全局按钮：`退出其他所有设备`，二次确认；当前会话是否保留必须在文案中明确。

### D. 数据与隐私

数据导出：

- `创建数据导出`。
- 显示 queued/running/completed/failed/expired 状态、创建和过期时间。
- 完成后 `下载导出文件`；强调一次性下载。
- 失败时 `重新创建`。

注销账号：

- 单独危险区域，不和普通资料保存并排。
- `申请注销账号` 打开确认弹窗。
- 弹窗说明立即禁用账号、撤销全部会话以及后台清理影响。
- 输入当前密码和确认语 `DELETE_MY_ACCOUNT`。
- 按钮：`提交注销`、`取消`。

## 7. 管理端页面详细规格

## 7.1 管理端全局规则

- 所有列表使用统一筛选条、表格、分页、列设置和详情抽屉。
- 筛选条件写入 URL，刷新和返回时保留。
- 表格数值使用等宽或 tabular numbers。
- ID、request_id、trace_id 提供复制图标。
- 时间显示本地时间，并可在 Tooltip 查看完整时间和时区。
- admin 写操作二次确认；operator 写按钮隐藏或禁用并说明原因。
- 管理操作成功后显示结果并刷新局部数据；失败必须展示稳定错误码和 request_id。

## 7.2 概览

### 指标

- AgentRun 总量、成功率、失败率、取消率。
- 排队中/运行中数量。
- P50/P95/P99 耗时（数据可用时）。
- 工具调用量与失败率。
- 模型 Token、成本、平均耗时。
- 知识库文档和索引状态。
- 待处理 DLQ/恢复项（目标态）。

### 内容区

- 运行趋势图。
- 失败原因分布。
- 最近异常运行表。
- 工具健康状态。
- 模型成本趋势。
- 最近管理操作。

### 按钮

- 时间范围选择。
- `刷新`。
- `查看全部运行`、`查看用量`、`查看异常`。
- 自动刷新开关和刷新间隔菜单（目标态）。

## 7.3 用户管理

### 列表

筛选：关键词、角色、状态、注册时间、最近登录；按钮 `重置筛选`。

列：用户 ID、用户名/展示名、邮箱、角色、状态、注册时间、最近登录、活跃会话数、操作。

行操作：

- `查看详情`
- 启用 / 禁用 / 锁定（按当前状态显示合法动作）
- `撤销全部登录会话`

### 用户详情抽屉/页面

Tabs：资料、饮食画像、登录会话、业务会话、操作历史。

admin 操作按钮必须展示影响范围；禁用或锁定用户前二次确认。operator 只能查看。

## 7.4 Agent 运行

### 列表

筛选：Run ID、用户、会话、状态、结果类型、时间、错误码、是否降级。

列：Run ID、用户、会话、状态、当前阶段、耗时、预算、工具数、结果类型、开始时间。

操作：`查看详情`；运行中可显示 `取消运行`（仅后端管理权限明确接入后启用）。

### 运行详情

- 摘要：状态、用户、会话、父 Run/接续 Run、创建/开始/完成时间。
- 事件时间线：事件序号、类型、时间、耗时；可识别缺口、重复、乱序。
- 预算：Token、成本、revision、追加记录和终止原因。
- 工具调用。
- 模型用量。
- 输入/输出摘要，敏感字段脱敏。
- 错误与降级原因。
- request_id / trace_id / dispatch_id。

按钮：`复制 ID`、`查看会话`、`查看工具调用`、`查看 Trace`、`导出诊断信息`（目标态）。

## 7.5 工具调用与 SQL 审计

页面使用 Tabs：`Tool Calls`、`SQL Audit`、`Trace`。

### Tool Calls

筛选：工具名、状态、风险级别、Run ID、时间。  
列：Call ID、Run ID、工具、版本、状态、耗时、重试次数、风险、创建时间。  
详情：输入/输出摘要、Schema 校验、权限、确认状态、错误码；敏感数据脱敏。

### SQL Audit

筛选：Run ID、执行状态、拒绝原因、时间。  
列：Audit ID、操作者、Run ID、语句类型、策略结果、执行耗时、行数、时间。  
详情：规范化 SQL、参数摘要、只读校验、超时/行数限制、错误信息。禁止展示数据库凭据。

### Trace

按 trace_id 聚合请求、Run、工具、模型、管理操作。提供复制、展开节点、仅看失败。

## 7.6 模型用量

筛选：时间、供应商、模型、场景、结果状态。  
指标：输入 Token、输出 Token、总成本、调用次数、平均耗时、失败率。  
图表：成本/Token 趋势、供应商占比、场景排行。  
表格：调用时间、Run ID、供应商、模型、场景、Token、成本、耗时、状态、价格版本。

按钮：`导出 CSV`（目标态）、`查看 Run`、`查看价格版本`。

## 7.7 管理知识库

### 列表

筛选：关键词、状态、可见性、文件类型、索引状态、上传时间。

列：文档 ID、标题、文件类型、大小、可见性、状态、索引状态、分块数、上传者、更新时间。

### 按钮

- `上传文档`：文件选择/拖放、格式和大小校验、上传进度。
- `查看详情`。
- `上线` / `下线`。
- `恢复`（已删除资源入口）。
- `重新索引`（目标态）。

详情显示：文件元数据、索引进度、错误原因、分块预览、权限/可见范围和操作历史。上传成功不等于索引成功，两种状态必须分开。

## 7.8 工具注册表

筛选：工具名、状态、风险等级、权限范围。  
列：名称、版本、状态、风险、超时、重试策略、权限范围、最近调用、失败率。  
详情 Tabs：概览、输入 Schema、输出 Schema、策略、近期调用。

admin 按钮：`启用` / `停用`，二次确认并说明会影响新 Run；operator 只读。工具创建、编辑和删除当前无真实接口，不设计为可用按钮。

## 7.9 删除资源

筛选：资源类型、删除者、删除时间、关键词。  
列：资源 ID、类型、名称/摘要、原所有者、删除者、删除时间、可恢复状态。

## 7.10 操作审计

筛选：操作者、动作、目标类型、结果、时间、request_id、trace_id。  
列：时间、操作者、动作、目标、结果、request_id、trace_id。  
详情：请求摘要、前后状态摘要、结果/错误码、客户端信息；敏感信息脱敏。

本节不进入首版管理端主导航和首版交付画板。后续可以先设计只读视图；任何“重放、跳过、强制完成”按钮必须等后端权限、幂等和审计契约明确后才能启用。

## 9. 视觉设计方向

### 9.1 关键词

可信、清爽、专注、食物与数据并重、具有轻微生活温度的专业工作台。

### 9.2 色彩

沿用但可优化现有基线：

| 用途 | 建议值 |
|---|---|
| 页面背景 | `#F7F5EF` |
| 主表面 | `#FFFFFF` |
| 主文字 | `#23251F` |
| 次级文字 | `#6F7468` |
| 边框 | `#D9D5C8` |
| 品牌主色 | `#2F6F4E` |
| 深主色 | `#1F4F38` |
| 强调色 | `#D88A3D` |
| 危险 | `#B94A48` |
| 信息 | `#326B8E` |

要求：

- 不把整套界面做成单一绿色或米色。
- 图表使用可区分、色盲友好的多色序列。
- 颜色不是状态的唯一表达方式。
- 正文和交互控件满足 WCAG AA 对比度。

### 9.3 排版与尺寸

- 中文 UI 字体：`Noto Sans SC`、`Microsoft YaHei` 或等价高可读字体。
- 数字：tabular numbers；ID/代码字段使用等宽字体。
- 不使用随视口宽度连续缩放的字号。
- 卡片和控件圆角不超过 8px。
- 普通控件高度建议 36-40px，移动端关键触控目标至少 44px。
- 桌面内容最大宽度按页面类型决定：表格与会话工作台可铺满，表单内容限制阅读宽度。

### 9.4 图标与图片

- 使用一致的线性图标库（代码落地优先沿用 Arco Icons；若后续替换需统一映射）。
- 熟悉命令使用图标：发送、停止、搜索、编辑、删除、复制、下载、刷新、展开。
- 不熟悉图标提供 Tooltip。
- 食物图片只用于真实记录或知识内容，不用模糊食物图库做页面装饰。

### 9.5 动效

- 只用于状态变化、层级切换和 Agent 执行反馈。
- 页面进入 150-240ms fade/轻微位移。
- 抽屉、折叠、工具轨迹使用短促平滑过渡。
- 流式回答不造成消息区和输入器跳动。
- 支持 `prefers-reduced-motion`，关闭非必要动效。

## 10. 响应式规则

### 桌面 `>= 1200px`

- 左侧栏、主区、会话右侧轨迹可同时存在。
- 表格优先完整显示关键列，次要列可通过列设置控制。
- 会话页整体不滚动，侧栏、消息区、轨迹区各自滚动，输入器固定。

### 平板 `768-1199px`

- 左侧栏折叠为图标栏或抽屉。
- 会话轨迹改为右侧抽屉。
- 表格固定首列/操作列，允许明确的横向滚动。

### 移动 `< 768px`

- 单列布局，顶部菜单打开导航抽屉。
- 会话输入器固定底部并适配安全区。
- 轨迹、引用、详情使用全屏抽屉或底部面板。
- 管理端允许横向表格，但优先提供摘要列表+详情抽屉；高频筛选折叠。
- 规划表由跨天表格切换为按天折叠列表。
- 任何按钮文字不得截断到无法辨认；长标题换行。

Figma 必做断点：1440×900、1024×768、390×844。核心会话页额外建议 1366×768，验证低高度视口。

## 11. 可访问性与内容规则

- 所有图标按钮有可读名称和 Tooltip。
- 键盘可到达所有交互元素，焦点样式清晰。
- 弹窗打开后焦点进入弹窗，关闭后返回触发元素。
- 表单错误紧邻字段，并提供页面级错误摘要（长表单）。
- 图表同时提供文字摘要或数据表入口。
- 状态不能只靠红/绿区分。
- Loading 文案说明正在加载什么；超过合理时间提供取消或重试。
- 错误文案包含：发生了什么、是否可重试、用户下一步；必要时显示 request_id。
- 不出现“mock”“占位”“后端未实现”等开发文案；未接入功能在代码落地时隐藏，而不是伪装可用。
- 不在页面里放大段“如何使用本页面”的说明，帮助内容进入 Tooltip、空态或帮助入口。

### 12.3 原型流程

至少连通以下可点击流程：

1. 登录 -> 工作台 -> 新建任务 -> 会话运行 -> 追问 -> 写入确认 -> 完成。
2. 会话搜索 -> 重命名 -> 归档 -> 回收站 -> 恢复。
3. 工作台 -> 记录一餐 -> 确认 -> 分析当天。

8. 管理端 -> 上传知识文档 -> 上传成功 -> 索引中 -> 索引失败/成功。

管理写操作额外包含：operator 无权限、admin 确认、提交中、成功、失败。

## 13. 设计验收清单

### 信息架构

- 用户能在两步内发起核心任务。
- 记录、分析、规划、知识和会话之间跳转关系明确。
- 管理端用户、Run、工具、模型、知识、审计能通过 ID/Trace 互相追踪。
- 普通用户看不到管理入口；operator 与 admin 权限视觉一致且无歧义。

### 功能完整性

- 本文列出的按钮均有明确结果、禁用条件或弹窗。
- 不存在点击后无去向的假控件。
- 删除、注销、禁用、停用、预算追加等操作有确认和失败态。
- 异步任务有进度、完成和失败回执。
- 数据为空时不使用伪造图表或假列表填充。

### 可开发性

- 三个断点无重叠、溢出或关键动作不可见。
- 组件和 Token 可直接映射到 React/Arco 实现。
- 表格、抽屉、弹窗、状态组件保持一致。
- 长中文、长 ID、错误文案和大数值不会撑破容器。
- 页面名称、路由和业务名词与本文一致。

### Agent 体验

- 用户始终知道 Agent 当前在做什么、是否还在运行、能否停止。
- 追问、确认、失败、降级和预算上限不会伪装成普通回答。
- 工具调用和引用可追踪，但不泄露隐藏推理或敏感参数。
- 用户能从结果继续执行：保存、分析、规划、查看记录或追问。

## 14. 禁止偏离项

- 不制作营销落地页作为首屏。
- 不把 FoodMate 设计成通用聊天机器人皮肤。
- 不使用超大 Hero、渐变球、装饰性漂浮卡片或大面积单色主题。
- 不在页面区块外再套无意义卡片，不做卡片嵌套卡片。
- 不增加商城、订阅付费、社区动态、好友、插件市场等未定义功能。
- 不把目标态功能伪装成当前已完成接口。
- 不显示内部 Prompt、Chain-of-Thought、数据库凭据或原始堆栈。
- 不用“永久删除”按钮冒充当前仅支持软删除和恢复的能力。
- 不让 operator 看见可误触的高风险写操作。

## 15. 本版范围决策

### 已采用的保守默认

1. 首个正式版本只服务个人用户，不建立家庭、成员档案、多人营养目标或成员级数据权限。
2. 产品形态固定为响应式 Web，桌面工作台优先，不单独设计原生 App。
3. 首个开发版本保留独立“饮食记录”模块：Agent 负责自然语言录入，记录页负责查看、校正、复制和删除结构化数据；对应后端接口需同步建设。
4. 用户端知识库首版仅检索管理员维护且已上线的内容，不开放私人文档上传或个人索引管理。
5. 个人资料拆成资料、记忆、安全、数据隐私四个稳定子模块，避免所有操作堆在一个长页面。
6. 管理端把 Tool Call、SQL Audit、Trace 归入同一治理域，但保留独立 Tab。
7. 首版管理端不交付运行治理页面，相关内容只保留为后续设计附录。
8. 不提供当前没有契约支持的永久删除、工具创建/编辑和 DLQ 强制重放按钮。
9. 首版仅交付浅色模式，使用语义化设计 Token，为后续暗色主题保留扩展能力。

### 已完成的关键范围确认

1. 产品仅面向个人用户。
2. 首版保留独立饮食记录页面。
3. 用户端知识库只检索管理员维护的内容，不开放私人文档上传。
4. 管理端运行治理不进入首版交付。
5. 首版不设计暗色模式。
