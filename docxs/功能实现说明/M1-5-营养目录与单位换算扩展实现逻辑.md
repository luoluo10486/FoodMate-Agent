# M1-5 营养目录与单位换算扩展实现逻辑

## 1. 实现范围

本次扩展在既有 M1-5 营养目录之上新增 USDA FoodData Central SR Legacy 的 12 个可追溯食材，覆盖蔬菜、肉类、鱼类、乳制品、水果和豆类的不同常见形态：

- 洋葱、土豆、西兰花；
- 70% 瘦肉/30% 脂肪熟牛肉、鸡腿肉、养殖三文鱼；
- 全脂马苏里拉奶酪、脱脂希腊酸奶；
- 嫩豆腐、带皮苹果、生扁豆、生黑豆。

食材数据使用 `nutrition_foods` 的每 100 g 营养基准，份量数据使用 `nutrition_unit_conversions`。本次不修改历史迁移，不删除或覆盖历史目录事实。

## 2. 数据来源与可追溯性

实现文件：

- `script/sql/FoodMate/seed/V8__nutrition_usda_directory_expansion_seed.sql`
- `script/sql/FoodMate/validation/V8__nutrition_usda_directory_expansion_validation.sql`
- `foodmate-infra/src/test/java/com/foodmate/infrastructure/persistence/NutritionExpansionV8SeedScriptTest.java`

来源为 USDA FoodData Central SR Legacy 2019-04-01 数据集。每条食材的 `source_version` 保留 FDC ID，每条份量规则保留 FDC ID 和 `food_portion.seq_num`。食材的热量、蛋白质、脂肪、碳水均直接取 `food_nutrient.csv` 的 `nutrient_id` 1008、1003、1004、1005。

份量换算采用 `gram_weight / amount` 归一化。例如 USDA 返回 3 oz = 85 g 时，系统保存 `28.3333 g/oz`；0.5 cup = 126 g 时，保存为 `252 g/cup`，避免把原始 amount 误当成一个完整单位。

## 3. 幂等和安全边界

- 食材使用稳定 ID `510049-510060`，同一 ID 重复执行时只更新该 seed 所拥有的字段，恢复其 `is_deleted=false` 状态。
- 份量使用稳定 ID `520049-520060`，重复执行不会创建重复规则。
- 目标单位固定为 `g`，倍率必须大于 0，食材和规则必须为 `approved` 且未软删除。
- 不根据食物名称推断密度，不把 ml、勺、碗等没有 USDA 克重依据的单位写入目录。
- `nutrition_foods` 仍以已审核目录为唯一营养来源；无法匹配的饮食明细继续保持 `pending`，不由模型估算。

## 4. 当前验证事实

2026-09-02 在本地 Docker PostgreSQL `FoodMate` 数据库执行 V8 seed 后：

- 新增食材 `12/12`，全部 `approved`、未软删除；
- 新增 USDA foodPortion 规则 `12/12`，全部指向有效食材；
- V8 validation 的无效食材、无效规则、外键不匹配和规则形状错误均为 `0`；
- 当前目录总计 `60` 条 approved 食材、`60` 条 USDA foodPortion 规则和 `75` 条精确质量换算，active conversion 共 `135` 条；
- 重复执行 seed 返回食材更新 `12` 行、份量新增 `0` 行，未产生重复主键或唯一键冲突。

验证命令：

```powershell
.\mvnw.cmd -pl foodmate-infra -am test '-Dtest=NutritionExpansionV8SeedScriptTest' '-Dsurefire.failIfNoSpecifiedTests=false'
docker exec foodmate-postgres psql --no-psqlrc --set ON_ERROR_STOP=1 --username postgres --dbname FoodMate --file /tmp/foodmate-v8-seed.sql
docker exec foodmate-postgres psql --no-psqlrc --set ON_ERROR_STOP=1 --username postgres --dbname FoodMate --file /tmp/foodmate-v8-validation.sql
```

该验证是本地业务目录验证，不代表营养学专家复核、医疗建议或生产数据发布。后续若要增加更多食材，继续使用新的 seed 编号和新的稳定 ID，不应原地修改已执行的 V8 文件。
