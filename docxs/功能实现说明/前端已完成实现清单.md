## 4. G1 前端基础设施

### 4.1 TypeScript/Vite 路径别名

- `foodmate-ui/tsconfig.json` 和 `foodmate-ui/vite.config.ts` 统一配置 `@/*` 指向 `src/*`。
- 页面、组件和服务使用同一别名规则，避免 Vite 能解析但 TypeScript 无法检查的分裂配置。
- 该边界已通过 `npm run typecheck` 和 `npm run build`。

### 4.2 Tailwind、shadcn/ui 与 FoodMate 语义 Token

- `src/styles/tokens.css` 建立 FoodMate 颜色、字体、间距、圆角、边框和状态变量，并作为 shadcn 组件和页面样式的语义来源。
- Tailwind 已接入 Vite，组件目录位于 `src/components/ui`，基础工具位于 `src/lib/utils.ts`。
- shadcn/ui 只负责可组合控件和可访问行为，工作台、消息流、Agent 轨迹和页面布局仍由 FoodMate 领域组件负责。
- 当前完成的是 shadcn/Radix 基础设施和 Arco 清理代码边界；这不表示所有领域页面都已完成 Figma 实际画板对照，也不把 CSS Modules 领域布局误写成 shadcn 组件本身。

### 4.3 图标使用边界

- 标准命令图标使用项目统一图标组件和 Lucide，已覆盖发送、停止、搜索、编辑、删除、复制、下载、刷新、展开等操作。
- 页面不直接写入 iconfont 字码、Unicode 图标或未经登记的内联矢量。
- 领域图标只有在资源来源、授权、字形类名和适配背景确认后才允许进入 iconfont 封装。
- 当前 iconfont 实体字体包和最终资源注册仍未确认，因此本阶段只关闭标准命令图标边界，iconfont 资源登记保持 `BLOCKED`。

## 5. G2 基础组件

### 5.1 基础控件与可访问交互

`src/components/ui` 已形成项目内可复用的基础组件边界，包括：

- `Button`：variant、size、disabled 和命令图标按钮语义。
- `Input`、`Textarea`：可访问名称、输入状态和表单承载。
- `Dialog`、`Sheet`：Escape 关闭、焦点归还、确认操作和详情侧栏。
- `Tooltip`：不熟悉图标的说明和 Provider 生命周期。
- `Tabs`、`Select`：键盘切换、选项提交和管理端查询 Tab。
- `Table`：原生表格语义、窄屏横向滚动容器和稳定列布局。
- `Card`、`Badge`、`Alert`、`Progress`、`Skeleton`、`DropdownMenu`：指标、状态、反馈、进度、加载和菜单场景。

`src/components/ui/components.test.tsx` 覆盖 15 条基础组件测试，验证 Button、Input/Textarea、Dialog/Sheet、Tooltip、Tabs、Select、Badge、Alert 和 Table 的关键行为。

## 6. G3 工作台与会话体验

### 6.1 工作台壳层

- `WorkspaceLayout` 提供左侧会话栏、顶部区域、主工作区和可选右侧 Trace rail。
- Chat 页面按 Figma `agent-chat-v2` 保持 `260px` 侧栏、`860px` 对话区、`320px` Trace rail 和 `68px` 顶部栏；消息区、Trace 和输入区分别保持局部滚动与稳定高度。
- 页面局部滚动限制在会话列表、消息区、Trace 和宽表容器，避免整个页面出现非设计稿滚动。

### 6.2 会话列表与 Composer

- 会话列表复用真实会话服务，保留搜索、归档、恢复、删除和历史分页语义。
- Composer 使用 shadcn `Input` 与 `Button`，保留发送、停止、真实 API/SSE 回调和禁用状态；`agent-chat-v2` 设计稿当前只提供追问输入和发送入口，未虚构附件控件。
- Enter 发送排除 IME 组合输入和 `keyCode=229`，Shift+Enter 保留换行，运行中可停止当前 Run。
- 首页快捷任务先填充 Composer，并通过可访问的输入/发送控件进入会话。
- 移动端快捷任务在 390x844 下按两列换行，内容宽度为 `343px`，不产生页面级横向溢出。

### 6.3 Agent 状态、消息流与轨迹

- `AgentStatusStrip`、`ResultCard`、`CitationBlock`、`ClarificationCard`、`ConfirmationCard` 和 `ToolTraceItem` 分别承载运行状态、结果、引用、追问、写入确认和工具轨迹。
- 已保留 `waiting_user`、确认、失败、取消、流式输出和完成等状态展示。
- 真实 SSE 事件、取消、断点续传和 mock replay 使用同一 UI 状态映射，不因视觉迁移重写服务端事件契约。
- 工具输入/输出只展示脱敏摘要，不展示隐藏推理、数据库凭据或未授权的敏感参数。

## 9. 状态、权限与敏感数据边界

### 9.1 已完成的状态处理

- 页面已覆盖默认、加载、空、错误、提交中、成功、失败和必要的过期状态。
- Agent 交互已覆盖运行中、追问、确认、取消、SSE 重连、预算提示、预算耗尽和安全降级等前端展示语义。
- 管理写操作已覆盖 operator 无权限、admin 二次确认、提交中、成功和失败；失败显示稳定错误码和请求标识。
- real 模式无法取得后端数据时显示空态、错误态或 `-`，不把 mock 样例伪装成真实数据。

### 9.2 当前已实现的权限边界

- 顶部管理入口仅对 `admin/operator` 展示；普通用户不应进入管理后台。
- operator 可查看管理数据，但管理写操作保持禁用或进入无权限状态。
- admin/superadmin 可执行已接入的高风险操作，并必须经过确认和审计状态机。
- 用户侧会话、消息和 AgentRun 继续依赖服务端当前用户归属校验；前端不自行扩大数据可见范围。

这里记录的是前端已实现并通过本地测试的权限矩阵；真实 API 的服务端授权、并发竞态和部署环境回归仍需独立验收。

### 9.3 敏感数据处理

- Tool、SQL 和 Trace 详情只展示脱敏摘要、查询哈希、策略、返回行数和链路元数据。
- 不在页面返回数据库凭据、访问令牌、密码、令牌哈希或隐藏推理内容。
- ID 复制只复制页面允许展示的公开标识，不绕过后端权限读取完整对象。
