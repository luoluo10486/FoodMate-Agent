# M2-3 管理后台与模型治理实现逻辑

## 1. 实现范围

M2-3 为管理员、运营人员和 superadmin 提供受权限控制的运营查询、状态变更、模型治理、脱敏导出和操作留痕。当前实现以本地业务正确性为完成口径，不把本地接口、单元测试或一次云调用解释为生产监控平台、生产告警或发布系统。

当前已经实现的业务范围：

- 用户、AgentRun、Tool Call、SQL Audit、Trace、知识库、回收站、DLQ 和操作审计的分页查询。
- 用户状态、会话撤销、工具启停、知识文档可见性、资源恢复、DLQ 人工重放和模型治理变更。
- provider/model/route、价格版本、预算/配额、用量和配置状态的受控查询。
- 管理端 real 模式加载真实数据、加载失败态、状态确认、revision/幂等键和安全导出。
- Trace 列表与脱敏 Trace 明细，包括运行时事件、工具、模型、SQL、SSE 和业务审计跨度。

生产级 Trace 存储、统一指标平台、告警通知、浏览器全量兼容矩阵、发布回滚自动化和大数据量报表不在本地业务门禁内。

## 2. Java 查询边界

### 2.1 API 层

`AdminOperationalQueryController` 位于 `foodmate-api`，统一入口为：

```text
GET /api/admin/queries/{resource}
GET /api/admin/queries/traces/{traceId}
```

`resource` 只允许 application service 中登记的资源集合。请求支持 `page`、`size`、`query`、`status`、`visibility`、`sort` 和 `direction`，角色先由控制器校验为 `admin`、`operator` 或 `superadmin`，业务查询仍由 application 编排。

Trace 明细的 `traceId` 在 application 层执行非空、长度和规范化校验；不存在的 Trace 返回稳定的 `NOT_FOUND`，不返回底层 SQL 错误或异常堆栈。

### 2.2 Application 层

`AdminOperationalQueryServiceImpl` 负责：

1. 规范化资源名、分页参数和排序字段。
2. 将 HTTP 查询转换为 `AdminOperationalQueryRepository.Query`。
3. 对每个资源选择明确的分页查询、计数查询和 DTO 映射。
4. 通过 `traceDetail(traceId)` 组合 Trace summary 与 span 列表。
5. 保持查询端口只暴露已经裁剪的行对象，不向上层泄漏 Mapper、SQL 或数据库模型。

application 端的 `AdminOperationalQueryRepository` 位于 `foodmate-application`，因此 application 不依赖 MyBatis 或 PostgreSQL 表结构。查询结果使用 `RunRow`、`TraceRow`、`TraceSpanRow` 等受限 record 表示。

## 3. Trace 脱敏聚合

`AdminOperationalQueryMapper` 是 PostgreSQL 查询适配器。Trace summary 以 `agent_runs.trace_id` 为根，按存在的业务事实生成可读链路和 span 数量。明细只聚合以下已持久化事实：

| 来源 | 展示字段 | 不展示 |
|---|---|---|
| `runtime_event_inbox_v2` | event ID、事件类型、状态、时间、事件序号 | 事件原始 payload |
| `tool_calls` | Tool 名称、状态、延迟、错误码 | 完整输入和输出 |
| `model_usage_logs` | scene/provider/model、状态、延迟 | Prompt、完整回答、API Key |
| `agent_run_sse_outbox` | SSE event 类型、状态、序号、错误码 | SSE 原始数据正文 |
| `sql_query_audits` | 查询哈希、状态、延迟、行数 | SQL 原文和结果行 |
| `operation_audits` | action、结果、错误码、时间 | 请求 JSON 和响应正文 |

查询在 SQL 层直接选择白名单字段，前端不能通过隐藏字段获得额外数据。所有来源均要求关联 Run 未软删除，工具、模型、SQL 和审计事实要求自身未软删除。span 由 `started_at`、`sequence_no` 和 `span_type` 稳定排序，便于重复读取和页面回放。

HTTP 响应使用 `AdminTraceDetailResponse`，只返回 `summary` 和 `spans`。响应字段包括 service、span type、name、status、时间、耗时、错误码和序号，不包含 Prompt、原始载荷、对象存储地址、对象键、令牌或密钥。

## 4. 管理写操作

管理写操作由 `AdminManagementService`、`ToolRegistryService`、`KnowledgeService`、`AdminDlqReplayController` 和 `ModelGovernanceAdminService` 分别承接，控制器只做参数转换和鉴权。共用以下业务约束：

- operator 只能读取安全摘要，不能执行状态变更或高敏导出。
- admin 可执行普通用户、普通工具、知识文档和受控资源操作。
- superadmin 才可执行高风险工具、全局模型路由/价格/预算和系统级导出。
- 所有变更校验当前资源状态和 `revision`，避免覆盖并发更新。
- 写入口接受 `Idempotency-Key`，重复请求复用已有事实，不重复产生业务副作用。
- 高危操作要求确认字段，确认摘要只使用安全参数摘要。
- 业务状态与成功操作审计在同一事务内提交；失败按统一失败审计策略保留失败事实。

知识文档发布、下线、删除、恢复和索引重试继续遵循 M2-1 的状态门禁；Trace 查询本身是只读操作，不写入新的业务审计记录。

## 5. 模型治理

`ModelGovernanceController` 和 `ModelGovernanceAdminService` 管理 provider/model/route、价格、预算和状态。治理数据保存：

- provider code、model name、scene、route 优先级和启用状态。
- timeout、retry policy、上下文/输出限制和能力声明。
- 单百万 Token 价格、币种、price version 和生效时间。
- 单 Run、单用户、单日和全局预算/配额。
- 用量、延迟、成本、状态和稳定错误分类。

API Key 不进入数据库治理表。`EnvironmentModelSecretStatusAdapter` 只返回是否已配置及不可逆指纹状态；后台不能读取密钥明文、长度、前后缀或可恢复信息。Runtime 通过当前进程环境或受控 Secret 注入读取 Chat/Embedding 凭据，Chat 与 Embedding 使用不同变量。

路由、模型、价格和预算版本写入用量事实。历史用量不会因当前价格变更而重算；禁用模型拒绝新请求，已开始的调用继续使用原快照。预算不足在模型调用前拒绝，返回稳定错误码。

## 6. 前端 real 模式

### 6.1 运行治理页面

`foodmate-ui/src/pages/AdminPage/tabs/RunsTab.tsx` 在 `VITE_AGENT_MODE=real` 时并行请求真实分页资源：

```text
/api/admin/queries/runs
/api/admin/queries/tool-calls
/api/admin/queries/sql-audits
/api/admin/queries/traces
/api/admin/queries/dlq
```

Trace 行打开详情后，`adminService.ts` 再请求：

```text
/api/admin/queries/traces/{traceId}
```

页面将 summary 映射为 Trace 事实，将 span 映射为时间线节点；请求失败显示错误状态，真实模式不会用 mock 数据替代。fixture 模式只用于页面视觉和交互预览。

### 6.2 其他管理页面

用户、工具、知识库、回收站、操作审计、模型治理和导出页面均遵循相同的 real/fixture 隔离规则。按钮调用真实 API 前经过确认 Dialog，页面显示服务端返回的成功、失败、冲突或空态，不在前端推断业务成功。

## 7. 安全导出与操作审计

`AdminExportService` 只允许导出白名单字段，并限制结果数量、有效期和一次性下载。导出任务保存资源、筛选条件、字段集合、发起人、状态和过期时间；下载资格消费后不可再次使用。

导出请求、生成失败和下载行为通过统一 `OperationAuditPort` 记录。审计只保存 action、target、result、错误码、关联 ID、参数摘要和安全结果摘要；禁止保存 Prompt、完整回答、文档原文、SQL 原文、对象键、预签名地址、Token 和 API Key。

## 8. 业务验证与证据边界

已有业务验证覆盖：

- Java 管理查询、Trace summary/span 聚合、脱敏字段和 `NOT_FOUND`。
- 管理角色矩阵、状态变更、revision、幂等键、确认和统一审计。
- 模型 route/price/budget 版本、密钥配置状态和失败关闭。
- 前端 real/fixture 隔离、Trace 详情加载、错误态和导航关联。
- Docker 中 Python Runtime、SiliconFlow Chat、`BAAI/bge-m3` 和 `Qwen/Qwen3-Embedding-0.6B` 的单次协议调用。

执行结果和具体测试数字以 `script/sql/FoodMate/EXECUTION_RECORD.md` 为准。上述证据不覆盖生产 Trace 平台、Prometheus/Grafana、告警通知、供应商控制台密钥轮换确认、生产发布回滚、大数据量性能或跨节点故障恢复。

## 9. 代码与注释约定

Java 公共控制器、application service、端口、适配器和对外 response 使用简洁中文 Javadoc，说明职责、权限和脱敏边界。类之间通过接口和 DTO 通信；API 不写 SQL，application 不依赖基础设施客户端，infra 不把数据库对象直接暴露给前端。提交前运行 Java 业务测试、ArchUnit、Spotless 和 Alibaba 规范检查，发现格式问题先使用项目既有格式化命令修复。
