## 2. 功能概述

### 2.1 功能目标

- 把前端会话、消息、登录态恢复切到真实 PostgreSQL 接口。
- 让用户能真实创建会话、查看消息、发送用户消息、重命名、归档、删除和恢复会话。
- 统一 Cookie + CSRF 的请求方式，替换掉前端 mock 数据。

### 2.2 适用范围

- 真实登录、注册、退出、密码重置。
- 会话列表、搜索、分页、重命名、归档、删除、恢复。
- 用户消息持久化与消息读取。
- 前端真实 API 接入、登录态恢复、错误展示。

### 2.3 不包含范围

- AgentRun 创建与运行状态机。
- Runtime 调度、SSE、AI assistant 回复。
- 工具调用、RAG、附件写入。

## 4. 功能点实现

### 4.1 真实登录、注册和退出

- 代码入口是 foodmate-api/src/main/java/com/foodmate/api/controller/AuthController.java。
- register 和 login 调用 UserAccountService，成功后由服务端签发 foodmate_session 和 foodmate_csrf Cookie。
- logout 撤销当前会话并清空相关 Cookie。
- 前端通过 frontend/src/services/authService.ts 和 frontend/src/services/apiClient.ts 发送真实请求，不再依赖 mock。

### 4.2 登录态恢复

- 应用启动时，前端调用 /api/users/me 检查当前 Cookie 是否仍有效。
- frontend/src/App.tsx 根据返回结果决定进入登录页还是工作台。
- 如果服务端返回 401，前端清空认证状态并回到登录页。
- 刷新页面后仍使用服务端会话，不伪造已登录状态。

### 4.3 会话创建、列表和搜索

- 代码入口是 SessionController.create、SessionController.list、SessionController.search。
- 创建时后端从当前登录用户取得 user_id，生成会话 ID 并写入 sessions。
- 列表和搜索都带用户归属条件，只能看到自己的会话。
- PostgreSQL 模式下按标题和消息正文匹配，并按分页数据返回。

### 4.4 会话重命名、归档、删除和恢复

- PATCH /api/sessions/{id} 只修改标题，不改变会话归属。
- archive 和 unarchive 只切换状态，不删除消息。
- DELETE /api/sessions/{id} 写入软删除字段，保留恢复机会。
- restore 要求会话属于当前用户且仍在恢复期内。

### 4.5 用户消息保存与读取

- POST /api/sessions/{id}/messages 只接受 role=user。
- UserAccountService 生成消息序号、写入 messages，并更新会话最近消息时间。
- GET /api/sessions/{id}/messages 按序读取已持久化消息。
- ChatPage.tsx 先显示发送中状态，再用服务端结果替换临时消息。
- 本阶段只保存用户消息，不生成 assistant 回复。

### 4.6 前端 API 封装与 CSRF

- frontend/src/services/apiClient.ts 统一处理 credentials: include、JSON 请求头和错误映射。
- POST、PATCH、DELETE 等非安全方法自动带 X-CSRF-Token。
- frontend/vite.config.ts 提供本地代理，满足后端同源 CSRF 校验。
- 页面层只处理统一后的成功、失败、401、403 和网络异常状态。
