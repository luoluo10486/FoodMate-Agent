## 1. 定位

本文是 FoodMate 前端实现入口。Phase 1 静态原型和 Phase 2 Mock 交互是历史建设阶段；当前 M1-2/M1-3 已接入真实认证、会话、消息、AgentRun SSE、取消和断线续传，M1-4 已接入预算确认、continuation、协调故障提示和安全降级展示。默认模型仍为 `deterministic:local`；真实云长稳、生产 RAG、完整 Tool/SQL 交互和生产质量治理仍是后续工作，不能从目标交互推断代码已完成。

前端第一轮目标：

- 让首页、会话页、分析页、规划页、个人资料页和管理后台入口具备可运行的静态或 mock 原型。
- 让会话页能在无后端情况下播放一轮 Agent mock 任务。
- 让追问卡、确认卡、工具轨迹、引用、失败和取消状态先在前端闭环。
- 为后续接入 `/foodmate/agent-runs/{agent_run_id}/events` SSE 事件保留数据结构和状态映射。

## 2. 技术栈决策

当前代码基线：

- React
- Vite
- TypeScript
- Arco Design（迁移前存量依赖，不作为新页面目标方案）
- CSS Modules

目标重构基线：

- React
- Vite
- TypeScript
- shadcn/ui（基于 Radix 的可组合基础组件）
- Tailwind CSS（shadcn/ui 的目标样式编译层，使用 Vite 集成）
- CSS Variables + FoodMate 语义化 design tokens
- iconfont（仅用于已有准确的品牌或领域矢量资产）
- 标准命令图标使用统一的代码图标组件；与 shadcn/ui 生态一致的图标实现可作为默认选择

目标依赖由 shadcn/ui 初始化和所选组件按需引入；至少需要 Tailwind/Vite 集成、`clsx`、`tailwind-merge`、`class-variance-authority`、`lucide-react`、Radix primitives 和通知组件。具体版本不在文档中锁死，安装时以 shadcn/ui 当前生成配置和项目 Node 版本兼容性为准。

选择 React 而不是 Vue 的原因：

- FoodMate 更像 Agent 工作台，不是普通表单后台；核心复杂度在消息流、工具轨迹、Agent 状态和事件回放。
- React 的组件组合和 TypeScript 契约适合承载 `AgentRun`、`ToolCall`、`SSEEvent` 这类状态驱动 UI。
- 后续接入 SSE、mock event replay、局部状态机和复杂业务卡片时，React 生态和 AI Coding Agent 生成稳定性更好。
- Vue 3 也可实现本项目，但当前文档、系统设计和执行路线已偏向 React，切换会增加文档和实现同步成本。

选择 shadcn/ui 的原因：

- shadcn/ui 提供可复制、可组合、可审查的基础组件代码，适合将 Figma 的组件变体和状态逐项映射到项目中。
- Radix 的可访问行为覆盖 Dialog、Sheet、Tooltip、Tabs、Select 等复杂交互，减少业务组件重复处理焦点、键盘和弹层关闭逻辑。
- 组件源码归项目所有，能够在不套用后台模板的前提下保留 FoodMate 的工作台布局、色彩、卡片层级和动效。
- iconfont 仅承载 Figma 或品牌资产中没有合适通用图标替代的领域矢量，避免把业务图标和普通控件图标混在同一套不可追踪资源中。

## 3. Phase 边界

Phase 1：静态 UI 原型

- 创建前端应用骨架。
- 实现首页、会话页、分析页、规划页的静态页面。
- 抽取共享组件，组件通过 props 接收 mock 数据。
- 覆盖空态、加载中、错误态、完成态等静态状态。

Phase 2：Mock 交互

- 使用前端本地 mock event sequence 模拟 AgentRun 生命周期。
- 支持消息发送后的状态推进、工具轨迹出现、答案逐步输出。
- 支持 `waiting_user` 追问流程和确认流程。
- 展示 `failed`、`cancelled` 和停止按钮；当前只有错误展示，重试入口待实现，见 `当前实现审计与完善计划.md` 的对应任务。

不属于 Phase 1-2：

- 不接真实后端。
- 不创建真实数据库、SSE 服务或认证系统。
- 不实现真实 RAG、Tool、SQL Agent、ModelService。
- 不引入大型全局状态方案，除非 Phase 2 事件回放复杂度证明必要。

## 4. 路由与页面

推荐路由：

| 路由 | 页面 | Phase |
|---|---|---|
| `/` | 首页 | Phase 1 |
| `/login` | Mock 登录入口、用户资料和鉴权状态占位 | Phase 1 |
| `/profile` | 个人资料页：昵称、头像、邮箱、营养目标、忌口、单位偏好、修改密码入口；Phase 2 先做 mock，真实接口接入属于后端认证/个人资料阶段 | Phase 2 mock / 后续真实接入 |
| `/admin/*` | 独立管理后台，仅 `admin/operator` 可见，包含概览与治理子页面；Phase 2 先做 mock，真实接口接入属于管理接口阶段 | Phase 2 mock / 后续真实接入 |
| `/chat/:session_id?` | 会话页 | Phase 1-2 |
| `/analysis` | 分析页 | Phase 1 |
| `/planning` | 规划页 | Phase 1 |
| `/knowledge` | 知识库检索占位 | Phase 1 |

路由行为：

- Phase 1 可以先使用前端路由，不依赖后端 session。
- 首页快捷任务可跳转到会话页并带入 mock prompt。
- 会话页如果没有 `session_id`，使用 mock 当前会话。
- 分析页和规划页第一版使用静态 mock 数据。
- `/login` 第一版提供 mock 登录、注册入口、忘记密码入口、用户资料、营养目标、权限范围和鉴权状态说明，不写入真实 token。
- `/profile` 第一版展示 mock 个人资料，后续接 `GET/PATCH /foodmate/users/me`、头像上传和修改密码接口。
- `/admin` 第一版展示 mock 管理概览，普通用户不可见；真实接入后根据 `/foodmate/auth/me` 的 `role` 控制入口和路由访问。
- `/admin/users`、`/admin/runs`、`/admin/tools`、`/admin/usage`、`/admin/knowledge`、`/admin/deleted` 为管理后台独立子路由，左侧后台导航必须真实跳转。
- `/knowledge` 第一版只展示知识库检索与 ACL 过滤占位，不接真实 RAG 接口。

真实认证接入后的路由守卫：

- 未登录访问受保护页面跳转 `/login?redirect=当前路径`。
- 登录过期时先调用 `/foodmate/auth/refresh`，刷新失败再跳转登录页。
- 普通用户访问 `/admin` 展示 403 权限不足状态。
- `operator` 可进入管理后台只读视图，涉及用户状态、工具启停、恢复删除资源等操作必须隐藏或禁用。
- `admin` 可看到完整管理入口和高风险操作确认。

- `components/ui/` 放 shadcn/ui 基础组件源码，只负责通用交互和可访问性。
- `lib/utils.ts` 放基础 `cn` 等无业务语义的小工具，不能承载页面编排。

### 5.1 样式共存与退场规则

迁移期间允许 Tailwind、CSS Variables、CSS Modules 和遗留 Arco 样式并存，但职责必须清晰：

| 样式层 | 可承担内容 | 禁止内容 |
|---|---|---|
| `tokens.css` | FoodMate 语义 Token、主题基础变量、字体和基础刻度 | 页面专用颜色、任意像素值和业务选择器 |
| Tailwind | `components/ui` 的 Variant、间距、尺寸、可访问状态和通用布局 | 复制业务页面的大段状态编排 |
| CSS Modules | Workspace、消息流、表格等复杂领域布局及局部响应式规则 | 覆盖 shadcn 基础组件内部样式或重建通用 Button/Input |
| `iconfont.css` | 字体声明和语义图标 class 的底层注册 | 在页面中直接暴露资源字码 |
| `arco-theme.css` 与 Arco 全局 CSS | 尚未迁移页面的临时兼容 | 新页面、新基础组件或新业务能力 |

同一 DOM 元素的颜色、间距、边框、圆角和交互状态只允许一个样式层拥有最终决定权。迁移某个页面时，先移除该页面对 Arco 组件和主题覆盖的依赖，再引入对应的 shadcn/ui 组件；禁止通过全局优先级覆盖让两套组件表面上同时生效。

## 6. shadcn/ui 使用策略

shadcn/ui 只负责可组合的基础控件和可访问交互，必须服务 FoodMate 的餐饮 Agent 工作台定位。

目标组件映射：

| shadcn/ui 组件 | FoodMate 用法 |
|---|---|
| `Button` | 发送、停止、确认、重试、快捷任务操作 |
| `Input` / `Textarea` | Composer 输入、搜索会话、追问回复 |
| `Dialog` | 高风险确认、保存计划、删除或恢复确认 |
| `Sheet` | 工具轨迹详情、引用详情、移动端侧栏 |
| `Tooltip` | 工具按钮、状态图标、不熟悉的操作 |
| `Tabs` | Tools / Agents 展开面板或管理视图占位 |
| `Table` | 餐食计划、分析明细、后续管理列表 |
| `Card` | 指标卡、结果卡、推荐任务卡的基础容器 |
| `Badge` | Agent 状态、Tool 状态、风险等级 |
| `Progress` | Agent 阶段推进、计划校验进度 |
| `Skeleton` | 页面加载和局部加载 |
| `Alert` / `Sonner` | 操作反馈、错误提示和非阻塞通知 |

必须自定义的场景：

- 工作台整体布局。
- 左侧会话栏。
- 底部 Composer。
- Tools / Agents 状态区。
- 消息流和 Agent 运行轨迹。
- ResultCard、CitationBlock、ClarificationCard、ConfirmationCard。
- FoodMate 的背景、卡片层级、餐饮相关色彩和轻量动效。

图标与矢量资产：

- 发送、停止、搜索、编辑、删除、复制、下载、刷新和展开等标准命令使用统一的代码图标组件，并提供 `aria-label` 和 Tooltip。
- Figma 或品牌资产存在准确的食物、营养、状态和品牌矢量时，使用 iconfont 的语义 class 或 React 封装；不在组件里直接写字码、Unicode 或随机内联 SVG。
- iconfont 没有对应资源时，使用许可明确的 Figma SVG 或代码图标，并登记资源来源、名称、尺寸和适配背景。

禁止事项：

- 不直接套用 shadcn 示例页面或其他后台模板。
- 不把所有内容都做成默认 Card。
- 不使用默认蓝色作为唯一主视觉。
- 不让组件库默认间距破坏 `1440 x 760` 单屏工作台结构。

## 7. 视觉与动效策略

视觉方向：

- shadcn/ui 控件的清晰度 + FoodMate 的温暖餐饮任务感。
- 浅色中性背景，搭配绿色、陶土橙、信息蓝和少量危险红。
- 页面应像一个每天可用的 Agent 工作台，而不是普通后台管理系统。

动效允许范围：

- 页面进入时的轻量 fade/slide。
- 首页任务卡 hover/focus 的轻微抬升和阴影变化。
- Agent 状态推进时的进度条和状态 Tag 过渡。
- 工具轨迹展开/收起时的高度或透明度过渡。
- 追问卡、确认卡出现时的轻量弹入。
- answer stream mock 输出时的文本逐步出现。

性能边界：

- Phase 1-2 优先使用 CSS transition / animation。
- 不引入 Framer Motion 等额外动画库，除非后续明确需要。

## 12. M1-4 Agent 治理交互

本节定义后续目标交互，当前前端尚未全部实现。

### 12.1 Runtime 协调异常

- 后端返回 HTTP 503、`error_code=RUNTIME_COORDINATION_UNAVAILABLE` 时，显示“系统暂时异常，请稍后重试”，不得显示 Redis、permit、lease 等内部实现细节。
- 已有 `run_id` 时先查询权威 Run 状态，不自动创建第二个 Run；只有服务端明确尚未创建 Run 时才允许自动重试一次。
- 登录、历史会话和消息查询仍可使用时，不得把整个页面伪装成离线。

### 12.2 预算提示与追加确认

- 70%：显示非阻塞预算提示，不打断当前回答。
- 85%：显示已进入节省模式及可能减少检索、Reflection 或改用经济模型。
- 100%：暂停新模型调用，展示当前已完成内容、可信部分结果、追加 Token/成本和确认按钮。
- 用户确认必须展示本次追加上限；提交时携带服务端确认令牌或摘要，按钮防重复提交，不自动重放。
- 用户拒绝、确认过期或追加达到服务端上限时，展示已有可信结果或明确终止原因，不伪造完整答案。

### 12.3 补参、审批与 continuation

- 普通缺参时，用户补充消息创建新的 continuation Run；UI 保留父 Run 追问和新 Run 的关联，但只订阅当前 active Run。
- 旧 Run 的目标状态 `superseded` 显示为“已由后续任务接续”，不显示为失败或取消；在契约和前端映射落地前不得提前解析该状态。
- 工具审批和预算追加恢复原 Run，并产生新的 dispatch attempt；UI 仍展示同一个业务任务，不创建第二张用户任务卡。
- 用户明显改变目标时按普通新任务处理，不能把旧任务的已确认动作自动带入。

### 12.4 Eval 后交付与安全降级

- Final Eval 通过前只展示业务进度，不渲染候选答案正文。
- `result_type=safety_degraded` 时展示安全说明和“请咨询医生或注册营养师”，不得展示被拦截的高风险候选答案。
- 当前没有人工审核人员，不展示“等待审核人员处理”或无限等待状态。
- 取消结果使用确定性摘要展示已完成、未完成和状态未知步骤，不在取消后继续追加模型生成内容。
