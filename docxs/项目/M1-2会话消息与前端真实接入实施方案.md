# M1-2 会话、消息与前端真实接入实施方案

## 1. 目标与边界

M1-2 将 FoodMate 前端的认证、会话和消息功能切换到真实 PostgreSQL API，并完成可恢复的会话管理与稳定的页面状态。

本阶段发送消息的成功语义仅为“用户消息已保存”。不创建 AgentRun，不派发 Runtime，不生成 AI 回复，不接入 SSE；这些能力全部留给 M1-3。

附件入口保留，但明确提示暂不支持发送附件，不上传文件、不创建附件记录、不展示伪造成功。

## 2. 已确认决策

| 项目 | 决策 |
|---|---|
| 认证 | 服务端 Cookie 会话校验；不引入前端 refresh token |
| 认证失效 | API `401` 清理前端身份并跳转登录页，保留原访问地址 |
| 无权限 | API `403` 留在当前页展示无权限状态 |
| 网络错误 | 不视为退出登录；保留当前页面数据并提供重试 |
| 会话删除 | 软删除，可恢复，恢复期 30 天；物理清理由后续后台任务负责 |
| 会话搜索 | 搜索本人未删除会话的标题和消息正文，返回会话摘要和命中片段 |
| 附件 | 保留入口和降级提示，不实施文件消息 |

## 3. 现状与缺口

已有后端基础接口：

| 地址 | 方法 | 当前能力 |
|---|---|---|
| `/api/sessions` | GET/POST | 读取和创建会话，无分页、搜索 |
| `/api/sessions/{id}` | DELETE | 当前实际为归档，不是软删除 |
| `/api/sessions/{id}/messages` | GET/POST | 读取和写入消息，无分页；可由客户端指定任意合法 role |
| `/api/users/me` | GET | Cookie 会话身份校验 |

主要缺口：重命名、归档/取消归档、软删除/恢复、搜索、分页、用户消息角色约束、统一 HTTP Client、登录/注册真实接入、聊天页真实消息接入、路由守卫和网络状态处理。

## 4. 后端实施

### 4.1 会话 API

新增或调整以下接口：

| 地址 | 方法 | 功能 |
|---|---|---|
| `/api/sessions` | GET | 分页读取本人未删除会话；支持 `page`、`size`、`q`、`status` |
| `/api/sessions` | POST | 创建会话；标题为空时使用“新会话” |
| `/api/sessions/{id}` | PATCH | 重命名；标题长度限制 1-255 |
| `/api/sessions/{id}/archive` | POST | 归档会话 |
| `/api/sessions/{id}/unarchive` | POST | 取消归档 |
| `/api/sessions/{id}` | DELETE | 软删除会话，写入 `is_deleted/deleted_at/deleted_by` |
| `/api/sessions/{id}/restore` | POST | 恢复未超过 30 天保留期的会话 |
| `/api/sessions/deleted` | GET | 分页读取本人可恢复的已删除会话 |

所有接口都通过当前 Cookie 用户获取 `user_id`，SQL 必须同时限制 `session_id` 与 `user_id`。资源不存在、已删除、归属错误统一返回 `NOT_FOUND`，避免枚举其他用户资源。

### 4.2 消息 API

| 地址 | 方法 | 功能 |
|---|---|---|
| `/api/sessions/{id}/messages` | GET | 按 `sequence_no` 稳定排序，支持游标或页码分页 |
| `/api/sessions/{id}/messages` | POST | 仅接受 `role=user`，保存用户消息并更新 `last_message_at` |

服务端生成消息序号，禁止前端指定 `assistant/system/tool` 角色。内容限制采用非空、最大长度和 UTF-8 文本校验；重复提交通过客户端请求 ID 或幂等键保证不产生重复用户消息。M1-2 不写 `agent_run_id`。

### 4.3 搜索与索引

先使用 PostgreSQL `ILIKE` 实现关键词搜索：匹配 `sessions.title` 或同一会话下 `messages.content`。查询只返回当前用户的未删除会话，以最近消息时间倒序，并聚合一个截断后的命中片段。

新增面向查询的索引：

- `sessions(user_id, is_deleted, status, last_message_at DESC)`
- `messages(session_id, is_deleted, sequence_no)` 保持现有索引
- 根据真实数据量评估后再增加 `messages.content` 的全文索引；M1-2 不提前引入向量检索。

### 4.4 数据与清理

涉及表：`sessions`、`messages`、`users`、`user_auth_sessions`。

会话软删除不立即删除消息；恢复时恢复会话本身，关联消息保持原状态。30 天后的物理清理任务只在后续明确实现，不由请求接口执行。

## 5. 前端实施

### 5.1 统一 API Client

新增统一客户端，负责：

- `credentials: 'include'`；
- 从 `foodmate_csrf` Cookie 读取 token，并为所有非安全方法发送 `X-CSRF-Token`；
- 统一解析 API 成功与错误包；
- `401` 清除本地认证状态并跳转 `/login?redirect=...`；
- `403` 抛出可展示的无权限错误；
- 网络异常、超时和服务器错误保留错误类型，供页面显示重试操作；
- 请求取消和页面卸载清理，避免会话切换时旧响应覆盖新页面。

### 5.2 认证与路由

登录、注册、登出、当前用户和密码重置调用真实 `/api/auth/*`、`/api/users/me` 接口。应用启动时调用当前用户接口建立认证状态；受保护路由等待校验完成后再渲染，未登录用户跳转登录页并保留原地址。

### 5.3 会话与聊天页面

`WorkspaceLayout` 和侧边栏改用真实会话列表，提供创建、搜索、重命名、归档、删除和恢复入口。`ChatPage` 根据路由会话 ID 加载真实消息，按 `sequence_no` 渲染；发送后乐观显示“发送中”，服务端成功后替换为持久化消息，失败时显示可重试状态。

附件按钮保留，点击显示“暂不支持发送附件”的明确提示。工具选择、Agent 选择保持当前降级状态，不能暗示已经生效。

### 5.4 页面状态

每个真实数据页面实现：首次加载、空会话、空消息、分页加载、搜索无结果、`401`、`403`、网络中断和可重试错误状态。切换会话时取消旧请求，防止消息串页。

## 6. 测试与验收

### 后端

- PostgreSQL HTTP E2E：注册、登录、Cookie/CSRF、创建、重命名、归档、软删除、恢复、搜索、消息写入和分页。
- 越权回归：用户 A 不可读取、修改、删除、恢复或搜索用户 B 的会话/消息。
- 消息角色回归：外部接口提交 `assistant/system/tool` 返回明确 4xx。
- 稳定排序与并发写入：分页不重不漏，序号唯一。
- 30 天恢复期边界：过期会话恢复被拒绝。

### 前端

- 浏览器 E2E：登录跳转、刷新后仍登录、登出、会话 CRUD、搜索、消息发送、失败重试与附件降级提示。
- Cookie/CSRF 矩阵：同源成功、缺失 CSRF 拒绝、会话失效 `401` 跳转、权限不足 `403` 留页。
- 网络中断：不清理登录状态，页面显示重试并避免旧请求覆盖新会话。

### 完成标准

只有在真实 PostgreSQL 下完成上述 HTTP 与浏览器 E2E，且前端涉及的认证、会话、消息页面不再回退 mock 后，M1-2 才可标记完成。Agent 回复、SSE 与运行态不纳入本阶段验收。

## 7. 实施顺序

1. 固化 API 错误码、分页响应和会话状态契约。
2. 扩展 PostgreSQL 会话/消息服务与控制器，补齐资源归属和软删除恢复。
3. 添加数据库索引与校验 SQL，并执行后端单元测试和 PostgreSQL HTTP E2E。
4. 落地统一前端 API Client、认证状态和路由守卫。
5. 替换登录、会话侧栏、聊天页和消息发送 mock。
6. 完成加载/空态/错误态、网络中断与附件降级。
7. 执行浏览器 E2E、跨域 Cookie/CSRF 验收，更新功能实现说明。

## 8. 回滚原则

数据库只新增索引或兼容字段时采用独立人工 SQL 与回滚 SQL；不删除现有会话和消息。前端通过现有 `VITE_AGENT_MODE` 保留开发期 mock 回退，但 real 模式接口失败不得伪造成功或静默展示 mock 数据。

## 9. M1-2 功能实现完成记录

> 模板提示：后续 AI 阅读本文档时，必须保留并遵守本句提示，不得把 M1-3 的 AgentRun、Runtime、AI 回复或 SSE 功能提前写入 M1-2。

### 9.1 会话创建

- 用户点击侧栏“新建 Agent 会话”后，前端调用 `POST /api/sessions`。
- 请求体传递标题和会话模式；没有标题时由后端使用“新会话”。
- 后端从 Cookie 会话中取得当前 `user_id`，生成会话 ID 并写入 `sessions`。
- 创建成功后刷新侧栏列表，并跳转到 `/chat/{session_id}`。
- 相关代码：
  - 后端：`foodmate-api/.../SessionController.java`、`foodmate-application/.../UserAccountService.java`
  - 前端：`foodmate-ui/src/services/sessionService.ts`、`foodmate-ui/src/layouts/WorkspaceLayout/WorkspaceLayout.tsx`

### 9.2 会话列表、分页和搜索

- 页面首次加载时调用 `GET /api/sessions`，按页读取当前用户未删除的会话。
- 搜索框输入内容后调用会话搜索接口，后端同时匹配会话标题和消息正文。
- PostgreSQL 模式下使用 `ILIKE` 查询，并按照最近消息时间倒序返回结果。
- 返回值包含 `items`、`page`、`size` 和 `total`，前端据此展示空态和结果数量。
- 查询条件始终带 `user_id` 和 `is_deleted=FALSE`，不能读到其他用户或已删除会话。
- 相关代码：`UserAccountService.listSessions`、`UserAccountService.searchSessions`、`SidebarSessionList.tsx`。

### 9.3 会话重命名

- 用户在会话菜单中选择“重命名”，前端打开输入框并带出当前标题。
- 确认后调用 `PATCH /api/sessions/{id}`，只提交新的 `title`。
- 前端限制输入框最多 255 个字符，后端再次校验非空和长度，避免只依赖浏览器校验。
- 更新成功后重新加载列表，保证侧栏显示服务端保存的标题。

### 9.4 归档和取消归档

- 普通会话菜单显示“归档”，已归档会话显示“取消归档”。
- 归档调用 `POST /api/sessions/{id}/archive`，取消归档调用 `POST /api/sessions/{id}/unarchive`。
- 后端只更新当前用户会话的 `status`，前端收到成功结果后刷新列表。
- 归档不删除消息，也不改变会话 ID；它和软删除是两个独立状态。

### 9.5 软删除、已删除列表和恢复

- 用户选择删除时调用 `DELETE /api/sessions/{id}`，后端写入 `is_deleted`、`deleted_at` 和 `deleted_by`。
- 删除操作不物理删除会话和消息，因此误删后仍有恢复机会。
- 侧栏的“已删除会话”入口调用 `GET /api/sessions/deleted`，只展示删除时间不超过 30 天的当前用户会话。
- 用户点击恢复后调用 `POST /api/sessions/{id}/restore`，后端要求会话属于当前用户且仍在 30 天恢复期内。
- 恢复成功后清理删除字段、恢复 `active` 状态，并刷新普通会话列表。
- 超过 30 天或不属于当前用户的会话统一返回资源不存在/不可恢复结果，不暴露资源信息。

### 9.6 消息读取和用户消息保存

- 进入 `/chat/{session_id}` 后，`ChatPage` 调用 `GET /api/sessions/{id}/messages` 加载服务端消息。
- 后端按 `sequence_no` 稳定排序，并支持分页参数；前端按返回顺序渲染消息。
- 用户发送内容时，前端先显示发送中状态，再调用 `POST /api/sessions/{id}/messages`。
- 后端只接受 `role=user`，服务端生成下一条 `sequence_no`，写入消息并更新会话的 `last_message_at`。
- 写入成功后使用持久化消息替换临时消息；失败时保留可重试状态，不伪造发送成功。
- 本阶段不创建 `agent_run_id`，也不生成 assistant 消息。
- 相关代码：`ChatPage.tsx`、`sessionService.ts`、`SessionController.java`、`UserAccountService.java`。

### 9.7 真实登录、注册和登录态恢复

- 登录和注册页面通过统一 API Client 调用真实 `/api/auth/*` 接口，不再依赖前端 mock 用户。
- 注册不再强制要求不存在的邮箱验证码 mock；提交账号信息后由服务端创建用户并建立 Cookie 会话。
- 应用启动时调用 `GET /api/users/me`，根据 Cookie 恢复当前用户；未登录时才进入登录页。
- 登录成功后保存当前认证状态，并按 `redirect` 参数返回用户原本访问的地址。
- 401 会清理前端认证状态并跳转登录页；网络错误不会误判为登出，页面保留重试能力。
- 相关代码：`foodmate-ui/src/services/authService.ts`、`foodmate-ui/src/services/apiClient.ts`、`foodmate-ui/src/App.tsx`、`LoginPage.tsx`。

### 9.8 忘记密码和密码重置

- 忘记密码表单调用真实密码重置请求接口，不再只显示本地 mock 成功提示。
- 新增 `/reset-password` 路由，页面从 URL 获取重置令牌并提交新密码。
- 页面分别处理令牌缺失、密码校验失败、服务端拒绝和重置成功状态；成功后回到登录页。
- 相关代码：`foodmate-ui/src/pages/ResetPasswordPage/ResetPasswordPage.tsx`、`LoginPage.tsx`、`authService.ts`。

### 9.9 统一 API Client、Cookie 和 CSRF

- 所有 M1-2 会话请求统一经过 `apiRequest`，自动补充 `credentials: include` 和 JSON 请求头。
- 对 POST、PATCH、DELETE 等非安全方法，从 `foodmate_csrf` Cookie 读取令牌并发送 `X-CSRF-Token`。
- 开发环境使用相对 `/api` 地址；Vite 将请求代理到 `http://127.0.0.1:8080` 并重写 Origin，满足后端同源 CSRF 校验。
- 生产环境可通过 `VITE_API_BASE_URL` 配置后端地址。
- Client 统一解析成功响应、业务错误、401、403、网络异常和请求取消，页面只处理可展示的错误状态。
- 相关代码：`foodmate-ui/src/services/apiClient.ts`、`foodmate-ui/vite.config.ts`。

- 后端真实 PostgreSQL E2E 已验证账号、会话、消息及数据隔离相关流程。

### 9.11 M1-2 完成边界
