## 2. 当前可执行：前端

在仓库根目录执行：

```powershell
cd foodmate-ui
npm install
npm run dev
```

Vite 将在终端打印本地访问地址。fixture 模式仍保留用于设计预览；real 模式下认证、会话、AgentRun、知识检索、管理查询和部分用户业务页面使用真实接口。本地启动前端本身不会自动启动或连接 Java 后端。

### 2.1 管理后台 real 模式业务检查

需要验证管理后台真实接口时，在 Java API 已启动且当前浏览器已有 admin/operator 会话的前提下执行：

```powershell
$env:VITE_AGENT_MODE = 'real'
$env:VITE_API_PROXY_TARGET = 'http://127.0.0.1:8080'
npm run typecheck
npm run test -- --run src/pages/AdminPage/tabs/UsersTab.test.tsx src/pages/AdminPage/tabs/RunsTab.test.tsx src/pages/AdminPage/AdminPage.test.tsx

```

真实只读入口包括 `/api/admin/queries/runs`、`/api/admin/queries/tool-calls`、`/api/admin/queries/sql-audits`、`/api/admin/users` 和 `/api/admin/dashboard`；写操作必须由页面确认流程发出 `Idempotency-Key`、`revision` 和确认字段。接口失败或无数据时页面显示错误/空态，不使用 fixture 回退。当前后端尚无 Trace 分页资源，real 模式 Trace 维持空态。

知识库 real 管理入口使用批量上传表单（来源类型、名称、版本、授权说明和幂等键），通过 `/api/admin/knowledge-documents/upload-batches` 提交；批次详情通过 `/api/admin/knowledge-upload-batches/{batchId}` 和 SSE 进度恢复，索引失败条目可手动重试。发布、下线、恢复和删除继续走管理员确认流程，接口失败不会回退到 fixture。

### 4.6 M2-1 Chat SSE 持久化回放业务验证

Chat 兼容入口统一使用：

```text
GET /api/chat/runs/{runId}/stream
```

数值型且已存在的 V1 Run 会进入 PostgreSQL-backed `V1RuntimeEventService`；旧字符串 Run 保留 RuntimeGateway 兼容路径。浏览器断线时优先发送服务返回的稳定 SSE ID：

```http
Last-Event-ID: sse_<previous-event-id>
```

服务端也接受数值游标，便于本地业务验证。已实际验证 `Last-Event-ID: 5` 能从本地 deterministic Run 回放后续 `run.completed` 终态，且终态只出现一次。控制器定向测试命令为：

```powershell

```

该验证只覆盖业务入口、鉴权、游标转换和持久化事件回放；吞吐、延迟、组件重启、ACK 丢失、重复投递和生产恢复不属于当前门禁。

### 4.7 Docker 应用容器与 M2-1 deterministic 业务闭环

Python Runtime 由 Compose 的 `agent-runtime` 服务启动，镜像入口是
`python runtime_server.py`，容器内监听 `9000`，宿主机默认映射为 `9002`。只启动该服务时，Compose 会按 `depends_on` 自动拉起 Redis、RocketMQ、Java 控制面及其健康依赖：

```powershell
docker compose --env-file .env -f docker/compose.yml up -d --build agent-runtime
Invoke-WebRequest http://localhost:9002/foodmate/internal/health/live
Invoke-WebRequest http://localhost:9002/foodmate/internal/health/ready
```

修改根目录 `.env` 后必须重新创建服务，单纯 `restart` 不会更新容器环境变量：

```powershell
docker compose --env-file .env -f docker/compose.yml up -d --force-recreate agent-runtime
docker inspect foodmate-agent-runtime --format '{{range .Config.Env}}{{println .}}{{end}}'
```

Docker 侧配置使用 `FOODMATE_DOCKER_*` 命名空间，由 Compose 映射为容器内的 `FOODMATE_*` 变量。RAG local 模式在容器网络内访问 `http://milvus:19530`；不能把 `localhost:19530` 作为容器内 Milvus 地址。真实 Chat/Embedding 密钥只能在轮换后通过环境注入，不能写入命令、日志或提交记录。

如果 Docker Desktop 所在网络要求通过代理访问 SiliconFlow，为 `agent-runtime` 设置
`FOODMATE_DOCKER_HTTP_PROXY` 和 `FOODMATE_DOCKER_HTTPS_PROXY`，并保持
`FOODMATE_DOCKER_NO_PROXY` 包含 `foodmate`、`redis`、`postgres`、`milvus`、`minio`
和 `rocketmq-proxy`。这些变量默认为空，代理只用于外部云请求；修改后必须执行
`docker compose --env-file .env -f docker/compose.yml up -d --force-recreate agent-runtime`。
本机代理端口未监听或 Docker 出站 TLS 失败时，Runtime 会返回稳定错误，不得关闭证书校验绕过。

2026-08-23 已在 Docker 应用容器中完成两种不产生外部费用的 M2-1 业务验证。默认 `stub` 模式使用 Redis 确定性索引；`local` 模式使用 deterministic embedding 和 Docker Milvus，未读取真实 API Key。`foodmate` 容器对内访问 `agent-runtime:9000`，Runtime 默认映射到宿主 `9002`，避免与 MinIO 的宿主 `9000` 冲突。2026-08-28 追加验证：stub 源码挂载 smoke 不探测 Milvus，local 源码挂载 smoke 在容器网络内通过 Milvus `/healthz` 后才允许进入 Worker 启动。
