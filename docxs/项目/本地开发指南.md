# FoodMate 本地开发指南

> 2026-08-13 更新：当前只做本地优先。不要按本文件中的 `dev/prod` 目标配置推断已经建立 staging/production；M1-5 第一切片已完成本地真实 Java/SQL/API 验证，但营养目录无 seed，编辑、完整 Tool Gateway 和更多确认状态仍待完成。M1-6 的当前范围是本地 Actuator、基础 metrics、双 JVM 压测和依赖重启恢复。数据库备份恢复暂不做。

## 1. 当前边界

截至 2026-08-13，前端已完成部分真实认证、会话、AgentRun SSE 和用户业务页的代码迁移；Java 已完成本地 `local` profile 下 M1-5 第一切片，包含饮食记录基础读写、分析、计划基础流程和 `meal_plan.save_plan` 确认；Python Agent Runtime 已存在并完成 M1-3/M1-4 的本地 deterministic stub、受控 Runtime、健康检查和跨进程链路验证。本指南中的“当前可执行”命令仍只覆盖已实际验证的入口；`local-stub` 不连接 PostgreSQL，营养目录 seed、编辑、完整业务 Tool/SQL 或生产级稳定性仍不可推断为已完成。

当前仓库没有可用于完整本地业务联调的 Docker/Compose 或 CI 工作流；本轮使用运行中的本地 PostgreSQL 和已启动 Java HTTP 服务完成了 M1-5 第一切片验证。完整营养目录、业务 Tool Gateway 和生产级治理仍未完成。不要把下文目标态当作现有能力。

## 2. 当前可执行：前端

在仓库根目录执行：

```powershell
cd foodmate-ui
npm install
npm run dev
```

Vite 将在终端打印本地访问地址。当前多数业务页面仍使用 `src/mock` 数据；认证、部分会话/AgentRun 和记忆页面已有真实接口接入，但本地启动前端本身不会自动启动或连接 Java 后端。

可单独执行的检查命令：

```powershell
cd foodmate-ui
npm run build
npm run lint
npm run test
```

已知基线（2026-07-11）：`npm run build` 通过；`npm run lint` 因 35 个 warning 与 `--max-warnings 0` 失败；`npm run test` 因没有匹配 `src/**/*.{test,spec}.{ts,tsx}` 的测试文件失败。失败不能作为通过门禁处理。

## 3. 当前可执行：Java stub

根 `pom.xml` 要求 Java 21 和 Maven 3.9+；优先使用仓库 Maven Wrapper：

```powershell
.\mvnw.cmd -pl foodmate-bootstrap -am package
& java -jar '.\foodmate-bootstrap\target\foodmate-bootstrap-0.1.0-SNAPSHOT.jar' '--spring.profiles.active=local-stub'
```

`application.yml` 的默认 profile 已是 `local-stub`。该 profile 排除 DataSource 和 Flyway 自动配置，并将 `foodmate.runtime.stub-enabled` 设为 `true`。启动后在另一个 PowerShell 中检查：

```powershell
Invoke-WebRequest http://localhost:8080/actuator/health
```

上述 JAR 路径和参数已于 2026-07-11 实际验证：`package` 成功，`/actuator/health` 返回 HTTP 200 和 `UP`，进程随后已终止。日常前台运行时使用 Ctrl+C 正常停止。当前审计基线为 `.\mvnw.cmd clean verify` 通过，14 个 Maven Reactor 项目成功，Surefire 共 29 个测试、0 failure/error/skipped。该结果只证明现有骨架和测试，不证明目标态业务链路。

## 4. 真实 PostgreSQL 配置路径：本地已验证

`local`、`dev` 和 `prod` profile 均启用 DataSource 与 Flyway；当前本地验证使用运行中的 Docker PostgreSQL 16 `FoodMate` 数据库，应用不会自动执行迁移。`application-local.yml` 包含可由 `DB_URL`、`DB_USERNAME`、`DB_PASSWORD` 覆盖的本地连接配置；不要把实际密码提交到 YAML、`.env` 或日志。已验证 Java HTTP 服务地址为 `http://localhost:18090`。

本地真实数据库结构、Java Repository、认证和 M1-5 第一切片 HTTP E2E 已验证；Redis/RocketMQ 未运行时健康状态仍可能为 `DOWN`，不应把单个业务 E2E 推断为完整依赖恢复或生产可用性。

## 5. 当前依赖与工作方式

前端依赖由 `foodmate-ui/package.json` 定义，开发入口是 Vite；其构建包含 TypeScript 检查。Java 根工程固定 Java 21、Spring Boot 3.5.16、MyBatis-Plus 3.5.16 和 Maven Enforcer。不要自行新增 Python、Docker 或 CI 命令来替代尚未存在的工程入口。

前端与 Java 可以分别运行；M1-5 第一切片已完成本地 HTTP、Cookie/CSRF 和 PostgreSQL 业务数据联调，但前端饮食/分析/规划页面仍未全部接入这些 API。开发 mock UI 时，必须把其结果视为原型行为；不能把 mock 结果标记为端到端完成。

## 6. Python Agent Runtime

当前已有独立 `agent-runtime`、`pyproject.toml`、V1 dispatch/cancel 路由、健康检查与 pytest。M1-3 使用确定性 stub；M1-4 已完成受控模型适配、Router、Planner、执行引擎、Proposal/Result 和本地恢复链路的实现与验证。真实云模型长期稳定性、生产级压测和 M1-5 业务工具仍未完成。

目标 Runtime 只处理推理、编排、RAG、模型调用、质量校验和回答组装。它必须通过已批准的 V1 内部契约与 Java 通信，不能使用业务数据库凭据，也不能直接读写业务表、Tool 或 SQL 执行面。

Python probe 路径固定为 `GET /foodmate/internal/health/live` 和 `GET /foodmate/internal/health/ready`。当前 Runtime 使用标准库 HTTP Server，不是 FastAPI；所有 Python health 调用必须保留完整的 `/foodmate/internal` 前缀。

## 7. 提交前最小检查

当前变更只涉及前端时运行 `npm run build`；涉及 Java 时运行 `.\mvnw.cmd clean verify`；涉及 Python Runtime 时使用项目定义的 Python 环境运行 pytest 和 Runtime 检查。M1-5 代码改造前，先按实施方案完成 SQL 评审和人工执行校验；双 JVM 压测及依赖重启恢复属于后续本地 M1-6 门禁。生产环境、Kubernetes、备份恢复和发布回滚不属于当前本地开发门禁。
