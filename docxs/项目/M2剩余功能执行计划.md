## 1. 目标与完成边界

本计划完成 FoodMate 功能版的剩余范围：M2-1 公共知识库与 RAG 收尾、M2-2 统一 Tool Gateway 与只读 SQL Agent、M2-3 真实管理后台与模型治理，以及当前前端业务构建门禁修复。

当前完成口径是“业务功能可运行、权限边界明确、核心业务测试通过”，不是生产就绪。以下内容统一后置，不得阻塞本计划：

- 渗透测试、完整漏洞治理、移动端专项和全浏览器兼容矩阵。

## 2. 已确认决策

1. SQL Agent 首期只读取当前用户自己的饮食记录、摄入汇总、餐食计划和购物清单，以及公共营养目录和公共知识元数据。
2. 用户、认证、令牌、密钥、完整审计内容、系统配置和其他用户数据不进入 SQL Agent 可见范围。
3. `calculator`、`time_parser`、`knowledge_search`、`database_query`、`food_log_writer`、`plan_validator` 和 `meal_plan.save_plan` 统一进入 Tool Registry；已有业务逻辑只接入治理层，不重写。
4. SQL Planner 支持 `local-stub` 确定性规则和 `local` OpenAI-compatible 模型两种模式。两种模式都必须经过同一 Java SQL Guard，真实模式失败不得自动回退并执行另一条 SQL。
5. 模型 API Key 仅由环境变量或 Secret 注入。管理后台只能显示配置状态或脱敏指纹，不能录入、读取、回显或导出明文密钥。
6. 后台权限固定为：`operator` 只读；`admin` 管理业务资源；`superadmin` 管理模型路由、价格、全局预算/配额和高风险工具。
7. fixture/mock 模式继续保留用于设计预览；`VITE_AGENT_MODE=real` 只使用真实 API，失败时不得回退 mock。
8. M2-1 `local` 支持 `deterministic` 和 `openai-compatible` 两种 embedding provider：当前业务验证使用本地确定性 provider + Docker Milvus，不需要 API Key；真实兼容服务仅在显式配置 endpoint、API Key 和 model 后切换，真实付费 API 不作为当前门槛。

### S1 Schema Catalog 与 SQL AST Guard

目标：Java 建立不可绕过的只读查询安全边界。

工作内容：

- Catalog 仅发布批准视图/字段，不发布 JDBC 凭据。
- SQL 使用成熟 parser/AST 校验；禁止字符串正则作为唯一防线。
- 只允许单条 `SELECT` 或 `WITH ... SELECT`；禁止写操作、DDL、多语句、注释穿透和未注册函数/表。
- Java 强制注入或验证当前用户过滤，限制行数、时间范围、执行超时和结果字节数。
- 敏感字段不进入 Catalog；结果再次按字段策略脱敏。
- SQL audit 保存问题摘要、SQL、状态、拒绝码、行数和耗时，不保存凭据。

业务验证：允许查询和攻击样例；跨用户、无过滤、敏感字段、写 SQL、多语句全部拒绝。

提交建议拆分：

- `feat(sql): publish authorized schema catalog`
- `feat(sql): enforce ast read-only guard and user scope`

### S2 双模式 SQL Planner 与 database_query

目标：Python 只提出结构化查询意图，Java 完成最终 SQL 授权与执行。

工作内容：

- stub 将有限自然语言意图映射为批准模板，不接受任意 SQL 文本。
- local 通过现有 OpenAI-compatible ModelService 产生结构化 proposal。
- proposal 包含 intent、time range、metrics、dimensions、filters 和候选 SQL；不包含 datasource 凭据。
- Java 根据 Run/user/Catalog 重建或校验最终 SQL，再由只读执行器运行。
- local 缺配置或模型失败返回稳定错误，不自动切 stub 执行。

业务验证：最近 7 天摄入、计划和营养目录查询；缺时间追问；无记录空态；模型非法 SQL 被 Java 拒绝。

提交建议拆分：

- `feat(sql-agent): add deterministic local planner`
- `feat(sql-agent): add model-backed structured planner`
- `feat(tools): connect authorized database query execution`

## 6. 当前测试门禁

## 7. 功能版完成定义

- 公共知识文档可以批量导入、索引、发布、检索、引用、下线和恢复。
- 七个工具由统一 Registry/Policy/Schema/Scope/Audit 治理。

- 管理后台 real 模式覆盖用户、Run、工具、知识、审计、回收站和模型治理。
- operator/admin/superadmin 权限矩阵生效，高危操作二次确认。
- stub 模式无需付费依赖，local 模式可以通过配置切换真实兼容服务。
- Java、Python、前端业务门禁通过；性能、故障和生产强化仍明确标为后置。
