# FoodMate 前后端接口覆盖矩阵

> 审计日期：2026-09-14
> 审计范围：`foodmate-api` 对外 HTTP/SSE 接口、`foodmate-ui` 真实模式 service 和页面入口。
> 本矩阵用于前端重构过程中的逐项收口，不代表所有接口已经完成真实联调。
> 历史证据章节按批次保留；当前接口状态以本矩阵表格和文档末尾最新证据为准。

## 1. 判定规则

“后端已实现”必须同时满足以下条件，不能只根据 Controller 文件存在来判断：

1. 路由、请求 DTO、响应 DTO 和错误码已经能够从代码中确认。
2. 鉴权、角色、CSRF、幂等键和版本冲突规则已经明确。
3. 前端有对应的 service 方法，真实模式没有用 Fixture 成功结果替代后端响应。
4. 页面覆盖加载中、空数据、失败、无权限、冲突和成功后的刷新行为。
5. 受影响模块有定向测试证据。

状态含义：

| 状态 | 含义 |
| --- | --- |
| `REAL_CONNECTED` | 前端 service 和页面已经使用真实接口，并有测试或联调证据。 |
| `SERVICE_ONLY` | 前端 service 已存在，但页面接入、状态覆盖或测试证据仍需补齐。 |
| `FIXTURE_ONLY` | 当前只有设计稿 Fixture，不能当作真实接口完成。 |
| `INTERNAL` | Java/Python 内部回调或 Runtime 通道，不直接由浏览器页面调用。 |
| `BLOCKED` | 缺少外部资料或运行前置条件，当前不能通过代码虚构完成。 |

后续每完成一个页面批次，必须同步更新“页面入口”“状态证据”和“最后验证提交”，再允许变更状态。

## 10. 更新要求

每个页面批次完成时，至少更新：

1. 对应接口的当前状态。
2. 页面和 service 文件路径。
3. 定向测试命令与结果。
4. 桌面、移动端和关键状态的人工复核结论。
5. 对应 Git 提交号。

只有接口、页面、状态、测试和证据全部存在时，才能从 `SERVICE_ONLY` 改为 `REAL_CONNECTED`。
