# FoodMate 人工 SQL 执行说明

## 执行顺序

1. 在目标库确认数据库名、账号、PostgreSQL 版本和当前脚本版本。
2. 按 `baseline/` 中的基线脚本完成空环境初始化；已有环境不得重复执行基线。
3. 按版本号顺序执行 `migration/` 中的增量脚本，从 V2 到当前最高版本 V25。
4. 每个迁移完成后，执行同名 `validation/` 脚本并保存只读结果。
5. 需要测试数据时，最后按需执行 `seed/`，并执行对应 seed validation。

迁移文件是唯一的结构变更来源。文件已经执行后不得原地修改；修正必须新增更高版本的迁移。目录中的 `rollback/` 只提供经评审的回滚前置条件和反向 SQL，不是故障时的自动恢复机制。

## 人工执行原则

- 当前脚本不会由 Java 启动自动扫描或执行。
- 执行前必须完成可验证的逻辑备份，并记录备份文件、SHA-256、数据库、执行人和开始时间。
- 不执行 `TRUNCATE`、宽泛 `DELETE`、直接修改 Flyway history 或跳过前置条件的回滚。
- 迁移脚本必须保持幂等边界；即使包含 `IF NOT EXISTS`，也必须执行 validation 确认最终结构。
- 生产环境、备份恢复和灾备演练不属于本地业务验证；本目录不能替代发布审批。

## 目录职责

| 目录 | 职责 |
|---|---|
| `baseline/` | 新环境的初始结构和基础约束 |
| `migration/` | 版本递增的人工增量结构变更 |
| `validation/` | 只读结构、索引、约束和业务事实校验 |
| `rollback/` | 回滚前置条件和对应反向 SQL |
| `seed/` | 明确版本的本地或受控业务种子数据 |
| `EXECUTION_RECORD.md` | 每轮实际执行台账和证据摘要 |

## 执行台账

每轮执行都要在 `EXECUTION_RECORD.md` 追加记录：时间和时区、环境、数据库版本、脚本版本、实际命令、validation 结果、保留数据范围、失败与补偿、执行人以及是否清理了本轮随机测试数据。未实际执行的迁移或联调不得写成已完成。

当前版本说明：V16-V17 为 M2-1 公共知识库，V18-V20 为 M2-2/M2-3 工具和管理契约，V21-V22 为模型治理，V23 为管理员导出任务，V24-V25 为 DLQ 重放和保留治理。详见 `migration/README.md` 及各版本配套 validation/rollback 文件。
